# 🔗 ИНТЕГРАЦИЯ MCP С TENDER SHIELD PRO

## 📋 КАНОНИЧЕСКИЙ ПАЙПЛАЙН С MCP

### Этап 1: Загрузка документов
```
Пользователь загружает:
- Проект_контракта.docx
- nmck.xlsx
- Обоснование_НМЦК.pdf
```

### Этап 2: MCP Обработка (ДО Decision Preview)

**2.1. MCP Pandoc → Markdown**
```
Обнаружен .docx файл → Используй MCP pandoc
→ Преобразуй Проект_контракта.docx в Markdown
→ Результат: структурированный текст для анализа
```

**2.2. MCP XLSX → Числовые значения**
```
Обнаружена таблица НМЦК → Используй MCP xlsx
→ Прочитай значение ячейки B12 из nmck.xlsx
→ Результат: точное значение НМЦК для расчётов
```

**2.3. MCP Python → Пересчёт / Проверка**
```
Обнаружены числовые данные → Используй MCP python
→ Посчитай: (22440 * 1.2 * 720) * 1.15
→ Результат: проверка расчётов, пересчёт с коэффициентами
```

### Этап 3: Evidence Objects
```
На основе обработанных данных создаются Evidence Objects:
- Точные цитаты из документов (через pandoc)
- Числовые значения (через xlsx)
- Проверенные расчёты (через python)
```

### Этап 4: Impact Logic
```
Для каждого риска формируется Impact Logic:
"Следствием является ... → Требуется ..."
```

### Этап 5: Decision Preview
```
Формируется Decision Preview с:
- Deal Snapshot
- Поле допустимых решений
- ИУН
- Реестр рисков с Impact Logic
- Блок фиксации ответственности
```

### Этап 6: Guardrails (БЕЗ MCP)
```
После Decision Preview:
- Language Guard
- Structural Guard
- Impact Guard
- Data Exhaustion Guard
```

---

## ⚠️ КРИТИЧЕСКИ ВАЖНО

### ❌ MCP НЕ используется после Decision Preview

**Запрещено:**
- Вызывать MCP для генерации текста решений
- Использовать MCP для пересчёта после фиксации решения
- Применять MCP в Guardrails

**Разрешено:**
- MCP только до Decision Preview
- MCP для точности данных, не для интеллекта
- MCP для обработки документов и расчётов

## 🎯 ТИПОВЫЕ СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ

### Сценарий 1: Обработка DOCX контракта

**Промпт для Cursor:**
```
Обнаружен файл Проект_контракта.docx.
Используй MCP pandoc для преобразования в Markdown.
Затем извлеки из результата:
- Условия оплаты
- Штрафные санкции
- Требования к обеспечению
```

**Ожидаемое поведение:**
1. Cursor вызывает MCP pandoc
2. Получает Markdown
3. Анализирует структурированный текст
4. Извлекает нужные данные

### Сценарий 2: Извлечение НМЦК из XLSX

**Промпт для Cursor:**
```
Обнаружен файл nmck.xlsx.
Используй MCP xlsx для чтения значения НМЦК.
Проверь ячейки: B12, C15, D20.
```

**Ожидаемое поведение:**
1. Cursor вызывает MCP xlsx
2. Читает значения из указанных ячеек
3. Использует точные значения для расчётов

### Сценарий 3: Пересчёт с коэффициентами

**Промпт для Cursor:**
```
НМЦК = 22440, коэффициент инфляции = 1.2, 
количество единиц = 720, НДС = 1.15.
Используй MCP python для расчёта итоговой суммы.
```

**Ожидаемое поведение:**
1. Cursor вызывает MCP python
2. Выполняет расчёт: (22440 * 1.2 * 720) * 1.15
3. Получает точный результат
4. Использует для Evidence Objects

## 🔧 КАК MCP ВЫЗЫВАЕТСЯ

### ❌ НЕ автоматически
MCP не вызывается автоматически при загрузке файлов.

### ✅ По промпту
MCP вызывается только когда Cursor получает явную инструкцию:
- "Используй MCP pandoc..."
- "Используй MCP xlsx..."
- "Используй MCP python..."

### 📌 MCP UTILIZATION CANON

В `.cursorrules` есть правила:
- Когда использовать каждый MCP сервер
- Как Cursor должен их вызывать
- Что делать с результатами

## 🚨 ТИПОВЫЕ ОШИБКИ (НЕ СДЕЛАЙ ЭТО)

### ❌ Ошибка 1: Вызов MCP из frontend
```
Frontend НЕ может вызывать MCP напрямую.
MCP доступен только в Cursor через промпты.
```

### ❌ Ошибка 2: Передача MCP ключей в DeepSeek
```
MCP ключи НЕ передаются в API вызовы.
MCP работает только внутри Cursor.
```

### ❌ Ошибка 3: Использование MCP для генерации решений
```
MCP НЕ используется для генерации текста решений.
MCP только для точности данных (документы, расчёты).
```

### ❌ Ошибка 4: Считать MCP "умнее модели"
```
MCP = инструмент точности, не интеллект.
MCP обрабатывает данные, но не принимает решения.
```
