# Безопасность MCP

## Что нельзя хранить в репозитории
Не коммитить:
- `%APPDATA%\\Cursor\\mcp.json` (локальный конфиг Cursor)
- пароли/токены/ключи в любых `.md`, `.json`, `.env`

В репозитории допускаются только шаблоны с плейсхолдерами (например `CHANGE_ME`).

## Особо опасные MCP-серверы (по последствиям)
Эти инструменты могут повлиять на состояние проекта/системы:
- `filesystem` — может переписать/удалить файлы
- `git` — может закоммитить/запушить
- `docker` — может остановить/удалить контейнеры, перезапустить сервисы
- `postgres` — может изменить данные

Правило команды: любые destructive-операции (удаление, overwrite, reset, drop table, push) выполняем только после явного подтверждения.

## Практика по БД
- В `mcp.json` используйте `DATABASE_URL` только локально.
- Рекомендуется отдельный пользователь БД для разработки.
- Для командной работы — хранить параметры подключения в `.env` (который игнорируется git), а не в markdown.

## Практика по логированию
Если логируете ошибки, следите чтобы в логи не попадали:
- `DATABASE_URL` целиком
- заголовки Authorization
- содержимое загруженных тендерных документов
