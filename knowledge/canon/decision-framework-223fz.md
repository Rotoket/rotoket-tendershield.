# 🎯 КАНОНИЧЕСКИЙ ФРЕЙМВОРК РЕШЕНИЙ — 223-ФЗ

**Стандартизированный алгоритм принятия решения об участии в закупке 223-ФЗ**

---

## 📊 МАТРИЦА РЕШЕНИЙ

### ШАГ 1: Выявление DEALBREAKER

**Если есть НЕ-митигируемый DEALBREAKER:**
- → **VERDICT:** `DO_NOT_PARTICIPATE`
- → **Обоснование:** Указать конкретный блокер
- → **Финансовое влияние:** 0 (не участвуем)

**Если есть митигируемый DEALBREAKER:**
- → Перейти к ШАГ 2

---

### ШАГ 2: Анализ митигации

**Для каждого митигируемого DEALBREAKER:**

1. **Проверить сроки:**
   - Можно ли решить до дедлайна подачи заявки?
   - Если НЕТ → `DO_NOT_PARTICIPATE`

2. **Проверить стоимость:**
   - Стоимость митигации ≤ 30% от НМЦК?
   - Если НЕТ → `DO_NOT_PARTICIPATE` (слишком дорого)

3. **Проверить вероятность успеха:**
   - Вероятность успешной митигации ≥ 70%?
   - Если НЕТ → `POSTPONE` (слишком рискованно)

**Если все митигируемые DEALBREAKER проходят проверки:**
- → Перейти к ШАГ 3

---

### ШАГ 3: Анализ CONTROLLED RISK

**Подсчитать количество CONTROLLED RISK:**

- **0-2 риска:** Низкая нагрузка
- **3-5 рисков:** Средняя нагрузка
- **6+ рисков:** Высокая нагрузка

**Для каждого CONTROLLED RISK:**

1. **Оценить финансовое влияние:**
   - Best case: +X руб. (прибыль)
   - Worst case: -Y руб. (убыток)
   - Вероятность Worst case: P%

2. **Оценить возможность митигации:**
   - Можно ли снизить риск?
   - Стоимость митигации: Z руб.

**Рассчитать общий Financial Impact:**
```
Best Case = НМЦК - Затраты - Митигация DEALBREAKER - Митигация RISK
Worst Case = НМЦК - Затраты - Митигация DEALBREAKER - Митигация RISK - Штрафы
Expected Value = Best Case * (1-P) + Worst Case * P
```

---

### ШАГ 4: Проверка соответствия Положению о закупках

**Для 223-ФЗ критично:**
- Документация должна соответствовать Положению о закупках заказчика
- Процедура должна соответствовать Положению
- Требования должны соответствовать Положению

**Если есть несоответствие:**
- → **VERDICT:** `POSTPONE` (до уточнения)
- → **Обоснование:** Указать несоответствие

---

### ШАГ 5: Принятие решения

**Если есть митигируемые DEALBREAKER:**
- → **VERDICT:** `PROCEED_WITH_CONDITIONS`
- → **Условия:** Список обязательных действий для митигации
- → **Action Plan:** Пошаговый план с дедлайнами

**Если нет DEALBREAKER, но много CONTROLLED RISK:**
- → **VERDICT:** `PROCEED_WITH_CONDITIONS` (если Expected Value > 0)
- → **VERDICT:** `POSTPONE` (если Expected Value < 0)

**Если нет DEALBREAKER и мало CONTROLLED RISK:**
- → **VERDICT:** `PROCEED` (если Expected Value > 0)
- → **VERDICT:** `POSTPONE` (если Expected Value < 0)

---

## 🔢 РАСЧЕТ ИУН (Индекс управленческой нагрузки)

**Формула:**
```
ИУН = Базовый риск (10)
    + DEALBREAKER (митигируемый: +20, не митигируемый: +30)
    + CONTROLLED RISK (количество × 5)
    + DEADLINE_TIGHT (+10)
    + LOGISTICS_COMPLEX (+10)
    + PENALTY_RISK (+5)
    + FINANCIAL_UNCERTAINTY (+10)
    + НЕСООТВЕТСТВИЕ ПОЛОЖЕНИЮ (+15)  # Специфично для 223-ФЗ
```

**Ограничение:** ИУН ограничен диапазоном 0-100

**Интерпретация:**
- **0-30:** Рутинно / делегируемо
- **31-50:** Требует контроля
- **51-70:** Только при личном внимании директора
- **71-100:** Неделегируемо / высокая управленческая нагрузка

---

## 📋 ОБЯЗАТЕЛЬНЫЕ ЭЛЕМЕНТЫ РЕШЕНИЯ

**Каждое решение должно содержать:**

1. **VERDICT:** PROCEED / PROCEED_WITH_CONDITIONS / DO_NOT_PARTICIPATE / POSTPONE
2. **Обоснование:** Почему именно это решение (ссылки на evidence)
3. **Financial Impact:** Best case, Worst case, Expected value
4. **ИУН:** Числовое значение (0-100)
5. **Action Plan:** Пошаговый план (если PROCEED_WITH_CONDITIONS)
6. **KB References:** Какие документы Knowledge Base использованы
7. **Соответствие Положению:** Проверка соответствия Положению о закупках (для 223-ФЗ)

---

## ✅ ПРОВЕРКА РЕШЕНИЯ

**Перед фиксацией решения проверить:**

- [ ] Все DEALBREAKER выявлены и классифицированы
- [ ] Проверено соответствие Положению о закупках (для 223-ФЗ)
- [ ] Financial Impact рассчитан корректно
- [ ] ИУН рассчитан по формуле
- [ ] Action Plan содержит дедлайны
- [ ] Все ссылки на KB валидны
- [ ] Решение логично и обосновано
