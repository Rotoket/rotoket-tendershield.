## ⚠️ ВЫЯВЛЕННЫЕ ПРОБЛЕМЫ

### Критические проблемы

#### 1. **Fallback пользователь в authService.ts**

**Проблема:**
В `frontend/src/services/authService.ts` (строки 130-177) при таймауте `/api/auth/me` создается fallback пользователь:

```typescript
const fallbackUser: AuthUser = {
  id: 0,
  email: normalizedEmail,
  is_active: true,
};
```

**Риски:**
- Пользователь может получить доступ без валидного токена
- Проблемы с правами доступа
- Нарушение безопасности

**Приоритет:** P0 (Критично)

**Решение:**
- Убрать fallback пользователя
- Улучшить обработку ошибок
- Добавить retry механизм с экспоненциальной задержкой
- Показывать пользователю понятное сообщение об ошибке

#### 2. **Таймаут 8 секунд может быть недостаточным**

**Проблема:**
В `authService.ts` таймаут для `/api/auth/me` установлен в 8 секунд (строка 125).

**Риски:**
- На медленных соединениях может быть недостаточно
- Приводит к созданию fallback пользователя

**Приоритет:** P1 (Высокий)

**Решение:**
- Увеличить таймаут до 15-20 секунд
- Добавить индикатор загрузки
- Реализовать retry механизм

### Средние проблемы

#### 3. **Отсутствие валидации email на фронтенде**

**Проблема:**
В `Auth.tsx` нет явной валидации формата email перед отправкой.

**Риски:**
- Отправка невалидных данных на backend
- Плохой UX

**Приоритет:** P2 (Средний)

**Решение:**
- Добавить валидацию email через regex или библиотеку
- Показывать ошибки валидации до отправки формы

#### 4. **Нет обработки сетевых ошибок**

**Проблема:**
В `authService.ts` при сетевых ошибках просто возвращается `null`, без уведомления пользователя.

**Риски:**
- Пользователь не понимает, что произошло
- Плохой UX

**Приоритет:** P2 (Средний)

**Решение:**
- Добавить обработку сетевых ошибок
- Показывать понятные сообщения пользователю
- Предлагать повторить попытку

### Низкие проблемы

#### 5. **Дублирование логики нормализации email**

**Проблема:**
Email нормализуется в нескольких местах:
- `authService.ts` (строка 95)
- `backend/auth.py` (строка 650)
- `backend/auth.py` (строка 141)

**Приоритет:** P3 (Низкий)

**Решение:**
- Вынести нормализацию в утилиту
- Использовать единую функцию везде

#### 6. **Отсутствие rate limiting на фронтенде**

**Проблема:**
Нет защиты от множественных попыток входа на фронтенде.

**Приоритет:** P3 (Низкий)

**Решение:**
- Добавить debounce для кнопки входа
- Блокировать повторные запросы до завершения текущего
