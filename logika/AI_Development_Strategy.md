# СТРАТЕГИЧЕСКИЙ ОТЧЁТ: РАЗВИТИЕ ИИ-АНАЛИЗА ТЕНДЕРОВ
## Почему текущий отчёт "сухой" и как это исправить

---

## ИСПОЛНИТЕЛЬНОЕ РЕЗЮМЕ

### Проблема
Ваш ИИ создаёт отчёты, которые:
- ❌ Перечисляют разделы контракта (а не анализируют суть)
- ❌ Содержат 15-20 блоков, половина которых пустые
- ❌ Не выделяют реперные точки (то, что волнует тендерника)
- ❌ Не выявляют риски и противоречия
- ❌ Не задают вопросы

**Результат**: отчёт неинформативный, такой продукт не купят.

### Решение (3 уровня)

| Уровень | Инвестиция | Результат | Срок |
|---|---|---|---|
| **1. Промпт-инженеринг** | 1-2 дня | +30% информативности | 1 неделя |
| **2. Специализированный LLM** | 2-4 недели | +70% информативности | 1-2 месяца |
| **3. Интеграция с базой знаний** | 1-2 месяца | +90% информативности | 2-3 месяца |

**Рекомендуемый путь**: начать с уровня 1, потом 2.

## ЧАСТЬ 1: ЧТО СЕЙЧАС ДЕЛАЕТ ИИ НЕПРАВИЛЬНО

### Ошибка 1: Буквальный анализ вместо аналитического

**Текущий подход**:
```
"Контракт содержит:
- Раздел 1: Предмет контракта
  * Сопровождение ПО медицинской ИС
  * На 150 АРМ
  * Срок 12 месяцев
  
- Раздел 2: Цена контракта
  * 541 800 руб
  * Источник: ОМС
  ...
```

**Проблема**: это просто копирование документа. Тендерник уже прочитал контракт.

**Нужный подход**:
```
"Закупка имеет средний уровень риска. Главная проблема: 
исполнитель должен принимать неограниченный объём 
запросов при фиксированной цене 541 тыс. руб/год. 
Это означает: если в месяц 1 запросов 4500, а в месяц 2 — 9000, 
исполнитель работает в убыток. Результат: либо отказ в обслуживании, 
либо ухода исполнителя с рынка."
```

**Разница**: первый — информационный шум, второй — инсайт.

---

### Ошибка 2: Отсутствие анализа рисков

**Текущий подход**: просто описывают параметры.

**Нужный подход**: 
1. Найди риск → 2. Объясни почему → 3. Оцени влияние → 4. Предложи решение

**Пример**:
```
РИСК: Нет штрафов за нарушение SLA

Почему это риск?
- ТЗ требует: ответить в 60 мин, решить в 5 дней
- НО: "превышение SLA не является просрочкой" (стр.6 ТЗ)
- Результат: исполнитель может регулярно нарушать SLA без наказания

Влияние:
- Низкое: пользователи ждут дольше, чем обещано
- Среднее: некоторые сложные вопросы остаются без ответа

Как исправить:
- Вариант 1: Удалить фразу "не является просрочкой"
- Вариант 2: Установить штрафы (5-10% от цены за нарушение)
- Вариант 3: Добавить условие: "3 месячных нарушения → расторжение контракта"
```

---

### Ошибка 3: Отсутствие противоречий

**Текущий подход**: просто читают каждый документ отдельно.

**Нужный подход**: ищут несоответствия между документами.

**Пример**:
```
ПРОТИВОРЕЧИЕ:

Требование 1 (к участнику):
"Требуется членство в СРО ОЦЕНЩИКОВ 
или 2+ оценщика в штате"

Объект закупки:
"Сопровождение программного обеспечения 
(консультирование пользователей ПО)"

Несоответствие:
Зачем оценщикам недвижимости консультировать по ПО? 
Это требование скопировано из другой закупки? 
Нужно требовать опыт в IT, а не в оценке.

Риск:
Может выиграть "ООО Оценочная контора", 
которая никогда не работала с ПО.
```

---

### Ошибка 4: Отсутствие исследования отсутствия

**Текущий подход**: описывают то, что есть.

**Нужный подход**: активно ищут то, что **НЕ упоминается** в документах.

**Пример**:
```
ЧЕГ НЕ ТРЕБУЕТСЯ (РИСК-СИГНАЛ):

❌ Не требуется: опыт в разработке ПО
❌ Не требуется: опыт в медицинских системах
❌ Не требуется: портфолио выполненных работ
❌ Не требуется: состав команды и её образование
❌ Не требуется: план резервных каналов обслуживания
❌ Не требуется: документирование результатов
❌ Не требуется: план переходного периода

Это означает: может выиграть компания без опыта.
```

---

### Ошибка 5: Очень много блоков, половина пустые

**Текущий отчёт**:
1. Резюме (пусто)
2. Объект закупки (пусто)
3. Описание объекта (повтор)
4. Технические требования (подробное перечисление)
5. SLA/КПИ (просто перечисление)
6. Требования к участникам (просто скопировано)
7. Цена контракта (простая цифра)
8. Обоснование цены (скопировано)
9. Финансирование (одна строка)
10. Расчёты (не нужны)
11. Сроки (одна строка)
12. Процедура (неинформативно)
13. Штрафы (просто числа)
14. Риски (неубедительно)
15. Вопросы (случайные)
16-20. Ещё какая-то информация

**Нужный отчёт**:
1. Резюме риска (суть в одном предложении)
2. Что покупаем (объяснение, а не перечисление)
3. Коммерческий анализ (цена + финансирование)
4. Риск-факторы (максимум 5, каждый с обоснованием)
5. Требования к участникам (анализ, не перечисление)
6. Вопросы для уточнения (конкретные, важные)

**Итого**: 6 разделов вместо 20. Но каждый — ценный.

## ЧАСТЬ 2: ТЕХНИЧЕСКОЕ РЕШЕНИЕ (АРХИТЕКТУРА)

### Вариант 1: Промпт-инженеринг (БЫСТРО)

**Что сделать**: переписать промпт для основного LLM

**Промпт-шаблон**:
```python
# В начало промпта добавить:

ROLE = "Вы - тендерный специалист с 30-летним стажем"

TASK = """
Проанализируйте тендерные документы и выдайте ТОЛЬКО:
1. Резюме риска (1 предложение, уровень: низкий/средний/высокий)
2. Суть закупки (объяснение, не перечисление)
3. Коммерческий анализ (цена + финансирование + реалистичность)
4. Риск-факторы (максимум 5, с обоснованием ПОЧЕМУ это риск)
5. Анализ требований к участникам (кто может выиграть?)
6. 3-5 конкретных вопросов для уточнения в РЗ
"""

CONSTRAINTS = """
- НЕ перечисляйте разделы контракта
- НЕ копируйте текст документов
- НЕ делайте отчёты больше 2 страниц
- ВЫДЕЛЯЙТЕ противоречия между документами
- ИЩИТЕ пробелы (чего НЕ требуется)
- ОЦЕНИВАЙТЕ реалистичность параметров
- ЗАДАВАЙТЕ вопросы
"""
```

**Время реализации**: 1-2 дня

**Результат**: +30% информативности

---

### Вариант 2: Специализированный LLM (ЛУЧШЕ)

**Архитектура**:
```
┌─────────────────────────────────────────┐
│ Документы (ТЗ, контракт, цены, требовает) │
└─────────────────┬───────────────────────┘
                  │
                  ↓
        ┌─────────────────────┐
        │  Парсер документов  │  ← извлекает структурированные данные
        └─────────────────────┘
                  │
        ┌─────────┼─────────┐
        ↓         ↓         ↓
    [ТЗ]    [Цена]    [Требования]
        │         │         │
        ↓         ↓         ↓
    ┌────────────────────────────────┐
    │  LLM-1: Анализ объекта         │ ← что? почему? как?
    │  LLM-2: Анализ рисков          │ ← найди противоречия
    │  LLM-3: Анализ цены            │ ← реалистично ли?
    │  LLM-4: Генерация вопросов     │ ← 5 вопросов для РЗ
    └────────────────────────────────┘
        │         │         │        │
        └─────────┼─────────┴────────┘
                  ↓
        ┌──────────────────────┐
        │  Агрегатор          │  ← объединяет в отчёт
        └──────────────────────┘
                  │
                  ↓
           [ИТОГОВЫЙ ОТЧЁТ]
```

**Преимущества**:
- Каждый LLM специализирован на одной задаче
- Быстрее и точнее, чем один большой LLM
- Легче отлаживать (если ошибка в анализе цены, меняем LLM-3)
- Можно добавить правила (if X then выделить красным)

**Время реализации**: 2-4 недели

**Результат**: +70% информативности

---

### Вариант 3: Интеграция с базой знаний (ЛУЧШЕ ВСЕГО)

**Что добавить**:
1. **База знаний по сферам** (государственные закупки, стройка, IT, медицина)
2. **История закупок** (примеры рисков из похожих тендеров)
3. **Правила анализа** (if цена < средняя на рынок, то выделить как риск)
4. **Справочники** (средние цены на услуги, типичные SLA и т.д.)

**RAG (Retrieval-Augmented Generation)**:
```
Пользователь загружает документы
        ↓
ИИ ищет в базе знаний похожие тендеры
        ↓
ИИ берёт контекст + примеры + выводы
        ↓
ИИ генерирует анализ с опорой на знания
```

**Примеры**:
```
Вопрос: "Цена 45 150 руб/месяц для сопровождения ПО на 150 АРМ — это нормально?"

БЕЗ базы знаний: "Цена указана в контракте"

С базой знаний: "По рынку (данные 2024-2025): 
- Средняя цена: 80 000 руб/месяц
- Ваша цена: 45 150 руб/месяц (на 44% ниже)
- Это экстремально низкая цена, риск качества"
```

**Время реализации**: 1-2 месяца

**Результат**: +90% информативности

## ЧАСТЬ 5: ИНСТРУКЦИИ ДЛЯ РАЗРАБОТЧИКА

### Если вы используете OpenAI API (GPT-4 / Claude)

```python
from langchain import OpenAI, PromptTemplate

# Системный промпт
SYSTEM_PROMPT = """
Вы - тендерный специалист с 30-летним стажем анализа государственных 
и коммерческих закупок. Ваша задача:

1. Прочитать тендерные документы
2. Выявить ТОЛЬКО критические риски и возможности
3. Выдать анализ в формате: резюме → объект → коммерчес → риски → вопросы

ОГРАНИЧЕНИЯ:
- Максимум 2 страницы
- Максимум 5 риск-факторов
- НЕ перечисляйте разделы контракта
- ИЩИТЕ противоречия между документами
- ЗАДАВАЙТЕ вопросы

ФОРМАТ ВЫХОДА:
## РЕЗЮМЕ РИСКА
[1 предложение, уровень риска]

## ОБЪЕКТ ЗАКУПКИ
[Объяснение, не перечисление]

## КОММЕРЧЕСКИЙ АНАЛИЗ
[Цена + финансирование + реалистичность]

## РИСК-ФАКТОРЫ (максимум 5)
[Каждый с ПОЧЕМУ и КАК ИСПРАВИТЬ]

## ТРЕБОВАНИЯ К УЧАСТНИКАМ
[Анализ, кто может выиграть]

## ВОПРОСЫ ДЛЯ УТОЧНЕНИЯ
[3-5 конкретных вопросов]
"""

# Вызов
llm = OpenAI(temperature=0.5)
response = llm(SYSTEM_PROMPT + documents_text)
print(response)
```

### Если вы используете локальный LLM (Ollama, LLaMA)

## КОНТРОЛЬНЫЙ ВОПРОС

Если ваш отчёт отвечает на эти вопросы тендерника, то он хороший:

1. ✅ Какой уровень риска в этой закупке? (высокий/средний/низкий)

Если хотя бы 3 из 5 вопросов остаются без ответа, отчёт нужно переделать.
