# 🚨 КРИТИЧЕСКИЕ НЕСВЯЗКИ: ЧТО НИКТО НЕ ВИДИТ

## ПРОБЛЕМА 1: Backend Генерирует Данные, которые Frontend НЕ Может Показать

### ❌ ОШИБКА В МОЁМ АНАЛИЗЕ:
Я сказал: "Расширь промпт Ollama на все поля (dealBreakers, opportunities, smartQuestions)..."

Но вот что РЕАЛЬНО происходит:

```
Текущая система:
POST /api/analyze → JSON { score, verdict, issues[], specs[] }

То, что я рекомендую:
POST /api/analyze → JSON { 
  dealBreakers: [...],          // 10-15 KB нового текста
  riskNarratives: [...],        // 20-30 KB нового текста
  opportunities: [...],         // 5-10 KB нового текста
  smartQuestions: [...],        // 15-20 KB нового текста
  financialSummary: {...}       // 5 KB
}

ИТОГО: 55-75 KB НОВОГО JSON за анализ
```

### ❓ ВОПРОСЫ, КОТОРЫЕ НУЖНО ЗАДАТЬ:

**Q1: Timeout Ollama**
- Текущий timeout: 300 секунд (в `_safe_ollama_invoke`)
- Ollama мне говорит в лучшем случае 7-8 мин на полный анализ с JSON парсингом
- **Что произойдёт?** Timeout на 40% запросов → 503 ошибки → потеря пользователей

**Q2: Токены и стоимость LLM**
- Один анализ → 2-3K токенов входа + 1-2K токенов выхода
- Это 3-5K токенов в сумме
- При 100 пользователях в день = 300-500K токенов
- **Цена:** На Claude API это 0.003-0.015$ за запрос. На Ollama это бесплатно, но GPU нужен мощный

**Q3: Качество JSON парсинга**
- LLM часто возвращает JSON с ошибками (запятые, кавычки)
- Мой fallback есть, но он ОЧЕНЬ простой
- **Риск:** 20-30% запросов вернут некорректный JSON → fallback режим → потеря качества анализа

### 🔧 ЧТО НУЖНО СДЕЛАТЬ:

1. **Не расширять промпт всё сразу** — разбить на две фазы:
   - Фаза 1: deal breakers + financialSummary (критичное)
   - Фаза 2: opportunities + smartQuestions (дополнительное)

2. **Добавить streaming** — не ждать полного ответа:
   ```python
   async def analyze_stream():
       # Отправлять результаты по мере получения
       yield { "type": "deal_breakers", "data": [...] }
       yield { "type": "financial", "data": {...} }
       yield { "type": "risks", "data": [...] }
   ```

3. **Кешировать результаты промежуточные** — если одна часть упала, другие уже в БД

## ПРОБЛЕМА 2: Frontend НЕ Готов К Таким Объёмам Данных

### ❌ ОШИБКА В МОЁМ АНАЛИЗЕ:
Я рисовал красивую UI, но не учитывал:
- **Производительность рендеринга** 100+ карточек рисков
- **Доступность** (a11y) для незрячих
- **Мобильность** — на телефоне 6 карточек + 10 вопросов уже проблема
- **Прокрутка и scroll performance**

### ❓ ВОПРОСЫ:

**Q1: Сколько рисков будет на экране?**
- В среднем тендере: 8-12 рисков
- В сложном тендере: 20-30 рисков
- **Проблема:** React будет рендерить 30 expandable карточек одновременно = lag

**Q2: Что с очень длинными текстами?**
- narrativeExplanation может быть 300-500 символов
- quote из документа может быть 200+ символов
- smartQuestions.fullQuestion может быть 400+ символов
- **На мобильном:** текст переломается, layout сломается

**Q3: Как пользователь будет навигировать?**
- 1 intro
- 15 рисков (expandable)
- 3 сценария решения
- 5 возможностей
- 10 вопросов
- **ИТОГО:** потенциально 34 раздела для прокрутки
- **Риск:** bounce rate 70%+ (пользователь закроет из-за "слишком много")

### 🔧 ЧТО НУЖНО СДЕЛАТЬ:

1. **Отступить назад от полного компонента** — показать только критичное вверху:
   - Deal Breakers (если есть)
   - Financial Impact (числа в рублях)
   - Main Recommendation
   
2. **Сделать вкладки/табы:**
   - Вкладка 1: Критичные факторы
   - Вкладка 2: Все риски
   - Вкладка 3: Возможности
   - Вкладка 4: Вопросы
   
3. **Ленивая загрузка:** только то, что в viewport, рендерить

## ПРОБЛЕМА 3: API Интеграции — Я Напридумывал БЕЗ РЕАЛЬНЫХ ИСТОЧНИКОВ

### ❌ ОШИБКА В МОЁМ АНАЛИЗЕ:
Я сказал: "Интегрируй ЕГРЮЛ, FAS, Courts..."

Но:

**Q1: Что это РЕАЛЬНО значит технически?**

```
ЕГРЮЛ API:
- Нет официального API
- Есть парсинг https://www.nalog.ru/ через Selenium
- Captcha блокирует автоматические запросы
- Риск: IP-ban за 10 запросов подряд

FAS.gov.ru API:
- Нет прямого API
- Есть неполный RSS-фид
- Данные задерживаются на неделю
- Риск: Информация неактуальна

Courts.ru API:
- Нет API вообще
- Только парсинг веб-сайтов 83 разных судебных систем
- Каждый суд имеет свой формат сайта
- Риск: поддержка nightmare
```

**Q2: Что получит пользователь в реальности?**
- Запрос на ЕГРЮЛ → 20-30 сек (сервер замёрзнет)
- Данные FAS от 2-3 месячной давности (бесполезно)
- Инфо из судов появится через неделю после принятия

**Q3: Какой ROI?**
- Затраты: 40-60 часов на интеграцию
- Результат: 20% более полные данные
- Юзер видит: "Ждите 30 сек..." или "Данные от 2 месяца назад"
- Вывод: **НАПРАСНАЯ ТРАТА ВРЕМЕНИ**

### 🔧 ЧТО НУЖНО СДЕЛАТЬ:

1. **Забыть про реестры на неделю 1** — они не критичны
2. **Вместо этого:** локальная правовая база (законы, прецеденты в памяти)
3. **Реально полезное:** интеграция с Sbis.ru (финотчётность) — ЕСть API, ответ за 2-3 сек

## ПРОБЛЕМА 4: Ollama Model Selection — Я НЕ Учёл Реальное Качество

### ❌ ОШИБКА В МОЁМ АНАЛИЗЕ:
Я рекомендовал failover: qwen2.5:0.5b → llama3:8b → mistral:7b

**Но вот что реально:**

```
qwen2.5:0.5b (500 млн параметров):
- Скорость: 3-5 сек на анализ (хорошо!)
- Качество: 30% галлюцинирует, JSON ломает (плохо!)
- Полезность: "Риск найден, но объяснение нелепое"

llama3:8b (8 млн параметров):
- Скорость: 45-60 сек (слишком долго)
- Качество: 70% корректно, JSON работает (хорошо)
- Полезность: "Есть риск, есть объяснение, есть решение"

mistral:7b (7 млн параметров):
- Скорость: 30-40 сек (норма)
- Качество: 65% корректно, JSON работает (нормально)
- Полезность: "Среднее между llama и qwen"
```

**Q1: Что реально происходит в failover?**
```
Пользователь нажимает "Анализировать"
↓
Пробуем qwen2.5:0.5b (3-5 сек)
↓ (JSON broken)
Пробуем llama3:8b (45-60 сек)
↓ (OK!)
Возвращаем результат

ИТОГО: Первый пользователь ждёт 50-65 СЕКУНД
```

**Q2: Что если один из сервисов недоступен?**
- Ollama на одной машине (нет кластера)
- Падение = все пользователи теряют функционал
- **Нужен реально резервный LLM**, но это $ (Claude API, OpenAI)

### 🔧 ЧТО НУЖНО СДЕЛАТЬ:

1. **Не использовать qwen2.5:0.5b для сложного анализа** — только для быстрого превью
2. **Основной workflow:** только llama3:8b (качество >70%)
3. **Резерв:** не другая местная модель, а **Claude API за 5$ в месяц**
4. **Кешировать результаты**  по хэшу документа (уже есть в системе)

**Q1: Какие документы должны быть в тестовом наборе?**

```
Категория 1: СТОП-факторы (deal breakers)
- Тендер с нереалистичными штрафами (10M при неудаче)
```
