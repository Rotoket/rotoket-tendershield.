# АНАЛИЗ ТЕНДЕРНЫХ ДОКУМЕНТОВ: ПРОФЕССИОНАЛЬНЫЙ ВЗГЛЯД
## Как обучить ИИ вычленять реперные точки

---

## ЧАСТЬ 1: АНАЛИЗ ТЕКУЩЕЙ СИТУАЦИИ

### Проблема
- ИИ создаёт отчёты с 15-20 блоками, половина которых пустые/неинформативные
- Отчёт получается **сухой**, без **действительной выжимки информации**
- Тендерный специалист ждёт **конкретных рисков и возможностей**, а не перечисления разделов

### Коренная причина
ИИ работает **буквально** (копирует структуру документов), а не **аналитически** (ищет **реперные точки** — то, что волнует опытного тендерника).

---

## ЧАСТЬ 2: РЕПЕРНЫЕ ТОЧКИ ПО СФЕРАМ

### 📋 СФЕРА 1: ГОСУДАРСТВЕННЫЕ/МУНИЦИПАЛЬНЫЕ ЗАКУПКИ (44-ФЗ)

#### Что ищет тендерник?

**1. ТРЕБОВАНИЯ К УЧАСТНИКАМ (ст.31 Закона 44-ФЗ)**
- Наличие/отсутствие требований — это РИСК-СИГНАЛ
- Часто "требования не установлены" = легкий вход некачественных подрядчиков
- Нужно проверить: требуется ли опыт, выполненные работы, квалификация?

**2. ЦЕНА И ФИНАНСИРОВАНИЕ**
- Метод определения НМЦК (берут ли данные из реальных предложений или справочников?)
- Коэффициент вариации цен (< 10% = однородный рынок, > 20% = разброс)
- Источник финансирования (бюджет = надёжен? ОМС = риск задержек)

**3. SLA/КАЧЕСТВЕННЫЕ ПОКАЗАТЕЛИ**
- Какие метрики контролируются?
- Есть ли защита от штрафов (как в этом случае: "нарушение SLA не является просрочкой")
- Есть ли асимметрия: требования к исполнителю острые, а штрафы слабые?

**4. ПРОТИВОРЕЧИЯ МЕЖДУ ДОКУМЕНТАМИ**
- ТЗ в описании объекта ≠ ТЗ в проекте контракта
- Требования в объявлении ≠ требования в бланке заявки
- Примеры: "Требование: 2+ разработчика, но в объявлении их не упоминают"

**5. ПРОЦЕДУРНЫЕ РИСКИ**
- Сроки подачи, рассмотрения, апелляций — достаточны ли?
- Порядок приёмки (через ЕИС = долгий цикл платежа)
- Есть ли уважительные причины для дисквалификации?

---

### 💼 СФЕРА 2: КОММЕРЧЕСКИЕ ЗАКУПКИ / ПРИВАТНЫЕ ТЕНДЕРЫ

#### Что ищет тендерник?

**1. КОММЕРЧЕСКИЕ УСЛОВИЯ**
- Есть ли штрафы за задержку? Размер и механизм?
- Гарантийные обязательства (сроки, объёмы)?
- Есть ли скидки на объём, сроки?

**2. ЗАЩИТА ОТ РИСКОВ**
- Страховка, залог, неустойка?
- Условия расторжения контракта?
- Кто несёт риск изменения цен?

**3. КОНКУРЕНТНОСТЬ**
- Есть ли преимущества для определённых типов компаний?
- Какова реальная цена (учитывая скрытые расходы)?

---

### 🏗️ СФЕРА 3: КОНСТРУКЦИИ/СТРОИТЕЛЬСТВО/НЕДВИЖИМОСТЬ

#### Что ищет тендерник?

**1. ТЕХНИЧЕСКИЕ ХАРАКТЕРИСТИКИ**
- Соответствие стандартам (ГОСТ, СНиП)?
- Материалы и методы (долговечность, качество)?

**2. ГАРАНТИИ И ДЕФЕКТЫ**
- Гарантийный срок на конструкцию?
- Кто устраняет дефекты (подрядчик или заказчик ищет другого)?

**3. УСЛОВИЯ ПРИЁМКИ**
- Испытания, экспертиза?
- Кто оплачивает проверки?

---

### 🏥 СФЕРА 4: УСЛУГИ / ПЕРЕВОЗКИ / ЛОГИСТИКА

#### Что ищет тендерник?

**1. УРОВЕНЬ ОБСЛУЖИВАНИЯ (SLA)**
- Время отклика, время решения?
- 24/7 или только в рабочие дни?
- Телефон, чат, email — какие каналы?

**2. ОБЪЁМ И НЕОПРЕДЕЛЁННОСТЬ**
- Фиксированный объём или "без ограничений"?
- Как считается переполнение?

**3. ГЕОГРАФИЧЕСКОЕ ПОКРЫТИЕ**
- Где оказывается услуга (очно, онлайн, гибрид)?

## ЧАСТЬ 3: ПРИМЕРЫ РЕПЕРНЫХ ТОЧЕК ИЗ ВАШИХ ДОКУМЕНТОВ

### ❌ ЧТО ИИ СКАЖЕТ СЕЙЧАС (НЕПРАВИЛЬНО)
```
"Сопровождение программного обеспечения МИС РГИСЗ СО включает:
- Приём обращений
- Консультационная поддержка пользователей
- Предельное количество АРМ: 150 шт."
```
**Результат**: никакой инфо для тендерника.

### ✅ ЧТО ДОЛЖЕН СКАЗАТЬ ИИ (ПРАВИЛЬНО)

**РЕЗЮМЕ РИСКА**
```
Закупка имеет СРЕДНИЙ уровень риска. Главный риск: 
исполнитель защищён от штрафов за нарушение SLA 
(время реакции 60 мин, время решения 5 дней), 
но принимать должен НЕОГРАНИЧЕННЫЙ объём запросов. 
Это создаёт асимметрию: нет верхних границ на работу, 
но при срыве SLA штраф не начисляется.
```

**ОБЪЕКТ ЗАКУПКИ**
```
Покупаются услуги консультационной поддержки (НЕ разработки, 
НЕ системного администрирования, только Q&A) для医疗 информационной 
системы с 150 рабочих мест. Услуга в удалённом режиме (риск: 
как проверить качество консультации?). Финансирование через ОМС 
(обязательное медстрахование) — есть история задержек платежей 
по этому источнику в регионе.
```

**ЦЕНОВОЙ АНАЛИЗ**
```
НМЦК = 541 800 руб/год = 45 150 руб/месяц для 150 АРМ 
= 301 руб/АРМ/месяц. Это примерно 10-12 руб за консультацию 
(если 30-40 консультаций в месяц на АРМ). Рынок однородный 
(коэффициент вариации 0.33%), что может указывать либо на 
стабильный рынок, либо на картельное соглашение.
```

**ГЛАВНЫЕ РИСКИ**

1. **АСИММЕТРИЯ SLA**
   - Исполнитель берёт обязательство отвечать в течение 60 мин
   - НО превышение SLA "не является просрочкой" (стр.6 ТЗ)
   - → Когда исполнитель начнёт отказывать в консультациях из-за перегрузки?

2. **ОТСУТСТВИЕ ВЕРХНЕЙ ГРАНИЦЫ ЗАПРОСОВ**
   - "Исполнитель должен принимать запросы БЕЗ ОГРАНИЧЕНИЯ"
   - → Нет бюджета на обслуживание 200 АРМ вместо 150?

3. **СЛАБЫЕ ТРЕБОВАНИЯ К УЧАСТНИКАМ**
   - Требование: "Член СРО оценщиков" (это для оценки недвижимости!)
   - Нет требований: к опыту в разработке/поддержке ПО, к составу команды
   - → Может выиграть компания без опыта в МИС

4. **ФИНАНСИРОВАНИЕ ЧЕРЕЗ ОМС**
   - Обязательное медстрахование часто "переревью" в конце года
   - Пример: "средства заморожены, переведены на другие нужды"
   - → Задержки платежей исполнителю

5. **СЛАБЫЕ ШТРАФЫ**
   - Штраф за неисполнение: 1% от цены (максимум 5 тыс.)
   - Для контракта на 541 800 это только 5,4 тыс. (максимум 5 тыс.)
   - → Недостаточна мотивация для качественного выполнения

**ВОПРОСЫ ДЛЯ УТОЧНЕНИЯ В РЗ**

1. Может ли исполнитель отказать в консультации если пик нагрузки?
2. Кто проверяет качество консультации и по каким критериям?
3. Есть ли история задержек платежей ОМС в поликлинике за 2024-2025?
4. Почему требование к СРО оценщиков, а не к разработчикам ПО?
5. Что будет с историей консультаций и кейсами после завершения контракта?
```

## ЧАСТЬ 4: ИНСТРУКЦИЯ ДЛЯ ИИ (ПРОМПТ)

### Как обучить ИИ вычленять реперные точки

```
ТЫ - ТЕНДЕРНЫЙ СПЕЦИАЛИСТ С 30-ЛЕТНИМ СТАЖЕМ.

Твоя задача: прочитать тендерные документы и вычленить ТОЛЬКО 
то, что волнует профессионала - риски, противоречия, асимметрии, 
отсутствие важного.

АЛГОРИТМ:

1. ПРОЧИТАЙ все документы (объявление, ТЗ, обоснование цены, проект контракта)

2. НАЙДИ ПРОТИВОРЕЧИЯ:
   - Объявление говорит X, контракт говорит Y?
   - ТЗ требует A, но штрафы за неисполнение A слабые?
   - Квалификация требуется, но проверки нет?

3. ОЦЕНИ РЕАЛИСТИЧНОСТЬ:
   - Цена: 301 руб/АРМ/месяц - это разумно для консультаций?
   - SLA: 60 мин ответ в удалённом режиме - достижимо?
   - Объём: "без ограничений" - это управляемо за эту цену?

4. ВЫДЕЛИ ОТСУТСТВИЕ ВАЖНОГО:
   - Нет требований к опыту? → РИСК
   - Нет требований к команде? → РИСК
   - Нет требований к резервным каналам? → РИСК
   - Нет требований к документированию? → РИСК

5. ЗАДАЙ 3-5 КРИТИЧЕСКИХ ВОПРОСОВ заказчику (для РЗ)

6. РЕЗЮМЕ: одно предложение, уровень риска, главная проблема

СТРУКТУРА ОТВЕТА:
- Резюме риска (1 предложение)
- Объект закупки (объяснение, НЕ перечисление)
- Коммерческий анализ
- 3-5 главных рисков (с обоснованием)
- 3-5 вопросов для уточнения

Объём: 1-2 страницы. НИКАКИХ 15-20 блоков!
```

## ЧАСТЬ 5: ТЕХНИЧЕСКИЕ РЕШЕНИЯ

### Вариант 1: Дополнительный LLM для анализа рисков

```python
# Рекомендуемая архитектура:

1. Парсер документов (извлекает структурированные данные)
2. LLM для анализа объекта (что покупаем, почему)
3. LLM для анализа рисков (красные флаги)
4. LLM для генерации вопросов (для РЗ)
5. Агрегатор (собирает в один отчёт)

Это БЫСТРЕЕ чем один большой LLM, и точнее в каждой задаче.
```

### Вариант 2: Обучение существующего LLM

- Fine-tuning на примерах "хороших" и "плохих" анализов
- RAG (поиск по аналогичным закупкам из истории)
- Промпт-инженеринг (описание алгоритма выше)

### Вариант 3: Гибридный подход

- Правила (если X, то выделить риск Y)
- LLM (для объяснения и вопросов)
- Базовые знания по сферам (государственные закупки, строительство и т.д.)

## ЧАСТЬ 6: РЕКОМЕНДАЦИИ

### ✅ ЧТО РАБОТАЕТ

1. **Анализ по сферам** (каждой сфере — свой набор реперных точек)
2. **Противоречия** между документами — всегда выдел
3. **Отсутствие требований** — активно ищи пробелы
4. **Асимметрия** (требования острые, штрафы слабые)
5. **Вопросы** для клиента — это то, за что платят

### ❌ ЧТО НЕ РАБОТАЕТ

1. ❌ Просто перечисление разделов
2. ❌ Копирование текста документов
3. ❌ 15-20 блоков в отчёте
4. ❌ Отсутствие анализа цены
5. ❌ Отсутствие анализа рисков

---

## ИТОГ

**Главное изменение**: ИИ должен анализировать **как тендерник**, а не **как парсер**. 

Это значит:
- Задавать вопросы (не просто читать)
- Выделять риски (не просто описывать)
- Искать противоречия (не просто перечислять)
- Генерировать ценные вопросы (не просто фактологию)

Если сделать это правильно, ваш продукт будут покупать 🚀
