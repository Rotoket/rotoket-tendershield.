# ШАГ 6: Audit Trail, Versioning & Decision Freshness

## Архитектурный контракт

Этот документ описывает Audit Trail, Versioning & Decision Freshness для Tender Shield Pro. Любые изменения логирования, версионирования, пересчёта решений НЕ ДОЛЖНЫ нарушать правила ниже.

## 🎯 Цель ШАГА 6

Обеспечить, чтобы любое управленческое решение в Tender Shield Pro было:
- воспроизводимым
- проверяемым
- привязанным ко времени и версии данных
- защищённым от «тихих изменений»
- явно помеченным как актуальное / устаревшее

**ШАГ 6 НЕ АНАЛИЗИРУЕТ**  
**ШАГ 6 НЕ ПРИНИМАЕТ РЕШЕНИЙ**  
**ШАГ 6 НЕ МЕНЯЕТ ВЫВОД**

Он ФИКСИРУЕТ И КОНТРОЛИРУЕТ.

## 🧱 Ключевой принцип (НЕ НАРУШАТЬ)

**РЕШЕНИЕ БЕЗ ИСТОРИИ = НЕДЕЙСТВИТЕЛЬНОЕ РЕШЕНИЕ**

## 1️⃣ Что такое Audit Trail в Tender Shield Pro

Audit Trail — это структурированная цепочка, а не лог событий.

```
Document Version
   ↓
Evidence Objects
   ↓
Risk Signals
   ↓
Decision Graph
   ↓
Decision Preview
```

Каждый уровень:
- имеет ID
- имеет timestamp
- имеет hash входных данных
- может быть восстановлен независимо

## 2️⃣ Обязательные артефакты ШАГА 6

### 1. Document Snapshot
```json
{
  "snapshot_id": "DS-2025-0012",
  "files": [...],
  "hash": "sha256",
  "created_at": "timestamp"
}
```

### 2. Evidence Snapshot
```json
{
  "evidence_set_id": "ES-014",
  "derived_from": "snapshot_id",
  "mcp_versions": {...}
}
```

### 3. Decision Snapshot
```json
{
  "decision_id": "D-0098",
  "derived_from": "evidence_set_id",
  "decision": "НЕ УЧАСТВОВАТЬ",
  "created_at": "timestamp"
}
```

## 3️⃣ Versioning — жёстко

Любое изменение:
- документа
- версии MCP
- нормализатора
- risk-логики
- decision-логики

➡️ **ОБЯЗАНО создавать НОВУЮ ВЕРСИЮ**, а не перезаписывать старую.

**❌ Запрещено:**
- «тихо» обновлять решение
- менять вывод без новой версии
- подменять Evidence задним числом

## 4️⃣ Актуальность решения (Decision Freshness Guard)

Каждое решение ОБЯЗАНО иметь статус:
- **ACTUAL** — актуально
- **STALE** — устарело
- **INVALIDATED** — инвалидировано

**Причины устаревания:**
- изменился ключевой документ
- добавлен новый файл
- изменён DEAL_BREAKER-Evidence
- обновлён MCP, влияющий на Evidence
- прошло заданное время (time decay)

**ШАГ 6 НЕ ПЕРЕСЧИТЫВАЕТ РЕШЕНИЕ,**  
**он ТОЛЬКО СИГНАЛИЗИРУЕТ, что решение больше нельзя считать актуальным.**

## 5️⃣ Разграничение ответственности

- **ШАГ 3** → создаёт Evidence
- **ШАГ 4** → формирует логику
- **ШАГ 5** → показывает решение
- **ШАГ 6** → охраняет доверие

**ШАГ 6 НЕ ИМЕЕТ ПРАВА:**
- менять классификацию риска
- смягчать DEAL_BREAKER
- «рекомендовать пересчёт»

Он только говорит:  
**«Это решение больше нельзя использовать».**

## 6️⃣ UI-правило (обязательно)

Если решение **STALE** или **INVALIDATED**:
- UI ОБЯЗАН показать предупреждение
- решение НЕ МОЖЕТ выглядеть актуальным
- любые PDF/выгрузки МАРКИРУЮТСЯ

**Запрещено:**
- скрывать устаревание
- показывать старое решение без метки
- позволять копировать вывод без статуса

## 7️⃣ Audit ≠ Transparency by Default

**Audit Trail НЕ ПОКАЗЫВАЕТСЯ директору по умолчанию**

Но ДОЛЖЕН БЫТЬ ДОСТУПЕН:
- юристу
- службе безопасности
- аудитору
- enterprise-клиенту

## 🚫 Строго запрещено в ШАГЕ 6

- удалять старые версии
- объединять версии
- «чинить» прошлые решения
- переписывать историю
- делать auto-update без явного нового Decision ID

## ✅ Критерий корректности ШАГА 6

Если:
- через год поднять старое решение
- восстановить snapshot
- пересчитать теми же версиями

➡️ **результат идентичен,**  
**и чётко видно, почему оно больше не актуально (если не актуально).**

## 📁 Структура кода

### `backend/audit_trail_types.py`
Определяет канонические типы:
- `DocumentSnapshot`
- `EvidenceSnapshot`
- `DecisionSnapshot`
- `AuditTrailChain`
- `DecisionFreshnessStatus`
- `FreshnessCheckResult`

### `backend/audit_trail_manager.py`
Менеджер Audit Trail:
- `AuditTrailManager` — создание snapshots
- `check_decision_freshness()` — проверка актуальности
- `invalidate_decision()` — инвалидация решения

### `frontend/src/components/audit/DecisionFreshnessGuard.tsx`
UI-компонент для отображения статуса актуальности:
- Предупреждение для STALE/INVALIDATED
- Скрыт для ACTUAL (по умолчанию)

## 🔄 Интеграция в пайплайн

1. **После загрузки файлов:** Создаётся `DocumentSnapshot`
2. **После ШАГА 3:** Создаётся `EvidenceSnapshot`
3. **После ШАГА 4/5:** Создаётся `DecisionSnapshot`
4. **При проверке решения:** Вызывается `check_decision_freshness()`
5. **В UI:** Отображается `DecisionFreshnessGuard` (если решение устарело)
