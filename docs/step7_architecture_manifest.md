- ✅ объясняет сложность решения
- ✅ хранит причины решений

## 1️⃣ Фундаментальные роли системы

### Система — НЕ:
- ❌ юрист
- ❌ финансист
- ❌ технадзор
- ❌ прогнозная модель
- ❌ источник истины по рынку

### Система — ДА:
- ✅ фильтр управляемости
- ✅ детектор блокирующих рисков
- ✅ объяснитель сложности решения
- ✅ хранилище причин решений

## 2️⃣ DEAL_BREAKER — абсолютный приоритет

**Правило системы:**

**Один DEAL_BREAKER важнее всех плюсов.**

### DEAL_BREAKER:
- не компенсируется
- не «взвешивается»
- не смягчается UI
- не оспаривается reasoning'ом

**Любая попытка:**
- «показать альтернативу»
- «снизить категоричность»
- «оставить на усмотрение»

➡️ **считается архитектурным дефектом.**

## 3️⃣ Особое мнение эксперта (обязательный слой)

### Назначение
Фиксировать обоснованные сомнения, которые:
- не являются DEAL_BREAKER
- не меняют решение
- но важны для защиты решения в будущем

### Правила
- не влияет на ИУН
- не влияет на Decision
- сохраняется в Audit Trail
- всегда отделено от Risk Signals

**❌ Запрещено:**
- превращать мнение в риск
- использовать как аргумент решения
- скрывать при аудите

## 4️⃣ Решение «НЕ УЧАСТВОВАТЬ» — стратегическая память

Каждое решение **НЕ УЧАСТВОВАТЬ** обязано:
- иметь Reason Codes
- быть агрегируемым
- использоваться как управленческая статистика

**Это:**
- не ML
- не оптимизация
- **корпоративная память отказов**

## 5️⃣ Границы ответственности (юридический guard)

### Система НИКОГДА не утверждает:
- ❌ «контракт безопасен»
- ❌ «участие выгодно»
- ❌ «риски приемлемы»
- ❌ «вероятность успеха X%»

### Система утверждает только:
**«Это решение управляемо / неуправляемо**  
**по зафиксированным причинам».**

Любая иная формулировка — нарушение контракта.

## 6️⃣ Анти-регрессионные правила (critical)

**Запрещено навсегда:**
- перенос логики в LLM «для удобства»
- автосмягчение формулировок
- скрытие сложности ради UX
- метрики без объяснения
- «временно упростить»

**Каждое упрощение:**
1. ➡️ сначала проверяется на управленческую ясность
2. ➡️ потом на UX
3. ➡️ и только потом на скорость

## 7️⃣ Критерий целостности системы

Если:
- сменить модель
- сменить команду
- сменить UI
- пересчитать через год

➡️ **Решение, его причины и ограничения остаются теми же.**

**Если нет — система сломана.**

## 📁 Структура кода

### `docs/ARCHITECTURE_MANIFEST.md`
Высший архитектурный контракт системы.

### `backend/decision_reason_codes.py`
Reason Codes для решений "НЕ УЧАСТВОВАТЬ":
- `DecisionReasonCode` — enum кодов причин
- `extract_reason_codes_from_decision()` — извлечение кодов
- `format_reason_codes_for_statistics()` — форматирование для статистики

### `backend/manifest_compliance_checker.py`
Автоматическая проверка соответствия Manifest:
- `check_deal_breaker_priority()` — проверка приоритета DEAL_BREAKER
- `check_decision_language()` — проверка языка решения
- `check_reason_codes_for_refusal()` — проверка Reason Codes
- `check_all()` — все проверки

## 🔄 Интеграция в пайплайн

1. **После создания Decision Snapshot:** Вызывается `ManifestComplianceChecker.check_all()`
2. **При решении "НЕ УЧАСТВОВАТЬ":** Извлекаются Reason Codes
3. **Reason Codes сохраняются:** В Decision Snapshot для корпоративной памяти
