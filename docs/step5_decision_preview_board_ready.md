# ШАГ 5: Decision Preview & Board-Ready Output

Преобразовать Decision Graph (ШАГ 4) в:
- однозначный управленческий вывод
- board-ready формат
- объяснимый нарратив для директора
- интерфейс, поддерживающий решение, а не анализ

**ШАГ 5 НЕ ПЕРЕСЧИТЫВАЕТ**  
**ШАГ 5 НЕ ДОБАВЛЯЕТ НОВЫЕ СМЫСЛЫ**

## 1️⃣ Decision Preview — обязательный формат

Любой вывод системы ДОЛЖЕН укладываться в этот шаблон (иначе считается архитектурной ошибкой):

### 🧭 Управленческий вывод

**Решение:**
- УЧАСТВОВАТЬ
- НЕ УЧАСТВОВАТЬ
- УЧАСТВОВАТЬ ТОЛЬКО ПРИ УСЛОВИЯХ

**Почему это решение:**
(2–4 причины, строго управленческие, не аналитические)

**Ключевой риск:**
- если есть DEAL_BREAKER — он здесь
- если нет — «критичных блокирующих рисков не выявлено»

**Управленческая нагрузка:**
- словесное объяснение
- без чисел
- без шкал
- через источники сложности

**Что нужно, чтобы изменить решение:**
- условия
- документы
- уточнения
(если применимо)

## 2️⃣ DEAL_BREAKER — правило вывода

Если в Decision Graph есть хотя бы один DEAL_BREAKER:
- решение НЕ МОЖЕТ быть «УЧАСТВОВАТЬ»
- интерфейс ОБЯЗАН визуально это отразить
- формулировка должна быть прямой, без смягчения

**❌ Запрещено:**
- «в целом приемлемо, но…»
- «можно рассмотреть при рисках…»

## 3️⃣ Управленческая ясность > полнота

**ШАГ 5 обязан скрывать:**
- второстепенные риски
- MARKET_NOISE
- технические детали
- длинные списки

**ШАГ 5 обязан показывать:**
- 1 главный вывод
- 2–4 причины
- 1 главный риск
- 1 источник управленческой сложности

## 4️⃣ Язык и тон (жёстко)

**Допустимый стиль:**
- деловой
- нейтральный
- уверенный
- без эмоций
- без запугивания

**Запрещено:**
- «катастрофа»
- «крайне опасно»
- «высокая вероятность провала»
- «LLM считает»
- «алгоритм определил»

## 5️⃣ UI — контракт, не творчество

**Интерфейс ШАГА 5:**
- подчёркивает решение
- не стимулирует «копаться»
- не превращается в дашборд рисков
- не даёт ощущения ложной точности

**Любая визуализация:**
- подчинена решению
- не подменяет управленческий вывод

## 6️⃣ Audit Trail (обязателен, но скрыт)

**ШАГ 5:**
- НЕ ПОКАЗЫВАЕТ аудит по умолчанию
- ОБЯЗАН сохранять ссылки:
  - Decision → Risk → Evidence
- аудит доступен по запросу, не в основном UI

## 🚫 Строго запрещено в ШАГЕ 5

- пересчитывать риски
- вводить новые формулировки риска
- добавлять «рекомендации от себя»
- показывать вероятности и проценты
- усложнять вывод «на всякий случай»

## ✅ Критерий корректности ШАГА 5

Если:
- директор читает только Decision Preview
- не открывает документы
- не читает аналитику

➡️ **он способен принять решение и не ошибиться в понимании.**

## 📁 Структура кода

### `backend/decision_preview_formatter.py`
Форматирование Decision Preview:
- `DecisionPreviewFormatter` — форматирование в board-ready формат
- `format_board_ready_text()` — текстовый формат для Board Pack
- `validate_preview()` — валидация на соответствие канону

### `frontend/src/components/audit/DecisionPreviewStep5.tsx`
UI компонент для ШАГА 5:
- Управленческий вывод (главное)
- DEAL_BREAKER (если есть, визуально выделен)
- Управляемые риски (скрыты по умолчанию)
- Audit Trail (скрыт, доступен по запросу)

## 🔄 Интеграция в пайплайн

1. ШАГ 4 формирует Decision Graph
2. ШАГ 5 получает Decision Graph
3. `DecisionPreviewFormatter.format_preview()` преобразует в board-ready формат
4. UI компонент отображает управленческий вывод
5. Audit Trail скрыт, доступен по запросу
