ЕДИНЫЙ ЭТАЛОННЫЙ PROMPT ДЛЯ CURSOR

(Tender Shield Pro / Система управленческого решения по тендерам)

---

0. Роль и цель системы

Ты разрабатываешь Tender Shield Pro — систему управленческого контроля решений по тендерам.

Система НЕ:

- не рекомендует,
- не советует,
- не “думает за директора”,
- не использует AI-лексику и вероятностные формулировки.

Система ДЕЛАЕТ:

- проводит формальный и фактический анализ документов,
- выявляет риски,
- связывает выводы с конкретными пунктами документов,
- рассчитывает Индекс управленческой нагрузки (ИУН) детерминированно,
- формирует управленческий вывод,
- фиксирует решение и audit trail.

---

1. Обязательный блок: Deal Snapshot (Контур сделки)

Этот блок ОБЯЗАТЕЛЕН для любого анализа. Без него анализ считается неполным.

**Deal Snapshot = 5 полей (без перегруза):**

1. **Предмет контракта**
   - из извещения / договора
   - если не найдено: «Не зафиксирован в документации»

2. **Цена контракта / НМЦК**
   - из извещения / обоснования НМЦК
   - если отсутствует: «Не зафиксирована в документах»

3. **Заказчик / Организатор**
   - из извещения
   - если отсутствует: «Не зафиксирован в паспорте документации»

4. **Правовой режим закупки**
   - 44-ФЗ / 223-ФЗ / иное
   - если встречаются расхождения → фиксировать как риск

5. **Состав пакета анализа**
   - «В анализ включено N ключевых документов (список)»

⚠️ Deal Snapshot отображается всегда на первом экране и в Board Pack.

---

2. Канон анализа документов (важно)

### 2.1 Ограничение пакета документов

По умолчанию: **3–5 ключевых документов**.

Режимы:

- «Ключевые документы» (default)
- «Расширенный пакет» (явно выбран пользователем)

Система обязана:

- предупреждать о росте ИУН при расширенном пакете,
- логировать `key_documents_selected`.

---

3. Риски и Evidence (ШАГ 8 — КРИТИЧЕСКИЙ)

### 3.1 Каждый риск ОБЯЗАН иметь Evidence

`Risk` без `Evidence` не может:

- влиять на решение,
- участвовать в расчёте ИУН,
- попадать в Board Pack.

### 3.2 Структура Evidence

```ts
evidence: {
  document_name: string,
  section_reference: string, // пункт / раздел / страница
  quote_excerpt: string,     // прямая цитата
  interpretation_type: 
    | "literal"
    | "conflict"
    | "absence"
    | "ambiguity"
}
```

### 3.3 Связь Risk ↔ Evidence

- Один риск → 1..N `evidence`.
- В UI: **управленческий вывод → по клику → цитата и источник**.

4. Индекс управленческой нагрузки (ИУН) — БЕЗ МАГИИ AI

### 4.1 Формула (детерминированная)

| Фактор                  | Условие                      | Баллы |
|-------------------------|------------------------------|-------|
| Conflict evidence       | evidence.interpretation=…    | +15   |
| Absence evidence        | evidence.interpretation=…    | +10   |
| Ambiguity evidence      | evidence.interpretation=…    | +5    |
| Финансовая неопределённость | ключевые параметры не зафиксированы явно | +10   |
| Расширенный пакет доков | режим «Расширенный пакет»    | +5    |
| Критический стоп-фактор | DEAL BREAKER = true          | +30   |

**ИУН = сумма факторов, ограниченная диапазоном 0–100.**

### 4.2 Диапазоны интерпретации

- **0–30** → Рутинно / делегируемо  
- **31–50** → Требует контроля  
- **51–70** → Только при личном внимании директора  
- **71–100** → Неделегируемо / высокая управленческая нагрузка

---

5. Правила итогового решения (ШАГ 4)

Когда **DEAL BREAKER НЕТ, но ИУН высокий**:

- система **НЕ запрещает участие**,  
- система формулирует:  
  **«Участие допустимо при управленческом контроле выявленных факторов»**.

Когда **DEAL BREAKER ЕСТЬ**:

- допустим вывод **«НЕ УЧАСТВОВАТЬ»**,  
- но:
  - строго с указанием `evidence`,
  - без эмоциональных формулировок.

---

7. Зоны осознанного молчания (ШАГ 10)

Система имеет право **не формулировать вывод**, если:

- недостаточно `evidence`,
- документ противоречив,
- информация отсутствует.

В UI:

- вывод скрыт по умолчанию,
- есть кнопка: **«Показать аналитический вывод» (только по инициативе директора)**.

Это усиливает доверие и юридическую защиту.

---

8. Audit Trail (ШАГ 6)

Каждое действие логируется:

- `key_documents_selected`
- `decision_draft_created`
- `decision_viewed`
- `management_load_high`
- `decision_confirmed_by_director`
- `board_pack_exported`

При фиксации решения:

```json
{
  "decision_basis": [
    { "risk_id": "...", "evidence_count": 2 }
  ]
}
```

Решение **необратимо** после подтверждения ответственности.

---

9. Board Pack (ШАГ 7)

### 9.1 Структура

**Страница 1 — для Совета директоров**

- Deal Snapshot  
- Итоговое решение  
- ИУН  
- Список ключевых факторов

**Страница 2 — для аудита / RAC**

- Все риски  
- Evidence  
- Расчёт ИУН

**Страница 3 — для юриста / проверяющего**

- Цитаты  
- Пункты документов  
- Audit Trail

### 9.2 Ограничения экспорта

Экспорт **ЗАПРЕЩЁН**, если:

- нет зафиксированного решения,
- нет `decision_recorded`,
- нет `decision_fixed`.

---

10. UI-гварды (обязательно)

Разработчик **НЕ МОЖЕТ**:

- добавить `risk` без `evidence`,
- изменить ИУН вручную,
- экспортировать Board Pack без решения,
- использовать запрещённую лексику.

---

Итог

Система:

- проводит анализ,
- показывает основания,
- не подменяет директора,
- оставляет проверяемый след,
- масштабируется на любые тендеры **без переписывания логики**.
