# Решение проблемы с кодировкой PostgreSQL

## Что было сделано

1. ✅ Создан общий файл `tests/conftest.py` с фикстурой `db_session` для всех тестов
2. ✅ Улучшена строка подключения к PostgreSQL с параметрами кодировки
3. ✅ Добавлен обработчик событий для автоматической установки UTF8 кодировки
4. ✅ Создан скрипт диагностики `check_db_connection.py`

## Быстрое решение

### Шаг 1: Проверьте подключение

```bash
python check_db_connection.py
```

### Шаг 2: Если база данных не существует, создайте её

Подключитесь к PostgreSQL:
```bash
psql -U postgres
```

Выполните:
```sql
CREATE DATABASE tender_shield ENCODING 'UTF8';
```

### Шаг 3: Если проблема с кодировкой остаётся

**Вариант A: Измените кодировку существующей БД**
```sql
ALTER DATABASE tender_shield SET client_encoding = 'UTF8';
```

**Вариант B: Переустановите PostgreSQL**

1. Удалите PostgreSQL 18
2. Установите PostgreSQL 16 (более стабильная версия)
3. При установке выберите:
   - Encoding: **UTF8**
   - Locale: **Russian, Russia**
4. Создайте БД:
   ```sql
   CREATE DATABASE tender_shield ENCODING 'UTF8';
   ```

### Шаг 4: Проверьте настройки в .env

Создайте файл `backend/.env`:
```env
TENDER_DB_USER=postgres
TENDER_DB_PASSWORD=ваш_пароль
TENDER_DB_HOST=localhost
TENDER_DB_PORT=5432
TENDER_DB_NAME=tender_shield
```

**Важно:** Убедитесь, что пароль не содержит проблемных символов (лучше использовать только латинские буквы и цифры).

### Шаг 5: Запустите тесты

```bash
pytest tests/ -v
```

## Что изменилось в коде

1. **database.py**: 
   - Добавлены параметры кодировки в URL подключения
   - Добавлен обработчик событий для установки UTF8 при каждом подключении
   - Улучшена обработка ошибок кодировки

2. **tests/conftest.py**: 
   - Создана общая фикстура `db_session` для всех тестов
   - Добавлена поддержка SQLite fallback для тестов

3. **check_db_connection.py**: 
   - Скрипт для диагностики проблем с БД
   - Проверяет подключение, кодировку и версию PostgreSQL

## Если ничего не помогает

Система автоматически переключится на SQLite для тестов, если PostgreSQL недоступен. Это временное решение, но тесты будут работать.

Для продакшена рекомендуется использовать PostgreSQL с правильной кодировкой UTF8.
