## 🔧 Как это работает

### Регистрация пользователя:

1. Пользователь заполняет форму (email, пароль, имя, организация)
2. Нажимает "Зарегистрироваться"
3. Frontend отправляет `POST /api/auth/register` с данными
4. Backend создает пользователя и возвращает `UserResponse`
5. Frontend автоматически выполняет вход (`POST /api/auth/login`)
6. Backend возвращает JWT токен
7. Frontend сохраняет токен в `localStorage`
8. Frontend получает информацию о пользователе (`GET /api/auth/me`)
9. Приложение переходит в основной интерфейс

### Вход пользователя:

1. Пользователь вводит email и пароль
2. Нажимает "Войти в систему"
3. Frontend отправляет `POST /api/auth/login` с данными
4. Backend проверяет credentials и возвращает JWT токен
5. Frontend сохраняет токен в `localStorage`
6. Frontend получает информацию о пользователе (`GET /api/auth/me`)
7. Приложение переходит в основной интерфейс

### Проверка авторизации при загрузке:

1. При загрузке приложения `App.tsx` проверяет наличие токена
2. Если токен есть, отправляется запрос `GET /api/auth/me`
3. Если токен валиден, пользователь автоматически авторизуется
4. Если токен невалиден/отсутствует, показывается форма входа

### API запросы с авторизацией:

Все запросы к API теперь автоматически включают заголовок:
```
Authorization: Bearer <jwt_token>
```

Токен берется из `localStorage` через функцию `getAuthHeaders()`.

## 🔐 Безопасность

1. **Хранение токена**: JWT токен хранится в `localStorage`
   - ⚠️ В продакшене рассмотрите использование `httpOnly` cookies для большей безопасности

2. **Срок действия токена**: По умолчанию 30 минут (настраивается в `backend/config.py`)

3. **Валидация токена**: При каждом запросе к `/api/auth/me` токен проверяется на сервере

4. **Выход из системы**: Токен удаляется из `localStorage`
