# ⚠️ Kill Switch — Использование только в экстренных случаях

## 🚨 ВАЖНО!

**Kill Switch должен активироваться ТОЛЬКО в экстренных ситуациях:**
- Обнаружены критичные ошибки в LLM-анализе
- Система выдает некорректные управленческие выводы
- Проблемы с безопасностью или качеством данных
- Требуется временная остановка анализа для критичного обновления/проверки

## ✅ Нормальный режим работы

**По умолчанию система всегда должна быть в режиме NORMAL:**
- Все функции доступны
- LLM-анализ активен
- Управленческие выводы формируются
- Полная функциональность системы

## 🚨 Когда активировать Kill Switch?

### Экстренные ситуации:

1. **Критичные ошибки LLM:**
   - Система выдает явно неправильные решения
   - Обнаружены систематические ошибки в анализе
   - LLM возвращает некорректные данные

2. **Проблемы безопасности:**
   - Обнаружены уязвимости в reasoning layer
   - Риск утечки данных через LLM
   - Компрометация системы

3. **Критичные обновления:**
   - Обновление промптов или логики
   - Миграция данных
   - Временная остановка для проверки

## ❌ Когда НЕ активировать:

- Обычная работа системы
- Плановое обслуживание (если можно обойтись без остановки)
- Тестирование (используйте тестовое окружение)
- Временные сбои LLM (если есть fallback)

## 🔧 Активация (только для администраторов)

### Через API:
```bash
POST /api/kill-switch/activate
Authorization: Bearer <admin_token>
Content-Type: application/json

{
  "trigger": "manual_admin",
  "reason": "КРИТИЧНАЯ ПРИЧИНА: обнаружены ошибки в LLM-анализе",
  "target_mode": "SAFE"
}
```

### Через скрипт:
```bash
cd backend
python -c "from kill_switch_manager import get_kill_switch_manager; from kill_switch_types import KillSwitchTrigger, SystemMode; ks = get_kill_switch_manager(); ks.activate(KillSwitchTrigger.MANUAL_ADMIN, 'КРИТИЧНАЯ ПРИЧИНА', SystemMode.SAFE)"
```

## ✅ Деактивация

### Через API:
```bash
POST /api/kill-switch/deactivate
Authorization: Bearer <admin_token>
Content-Type: application/json

{
  "reason": "Проблема решена, возврат в нормальный режим"
}
```

### Через скрипт:
```bash
cd backend
python deactivate_kill_switch.py
```

## 📊 Проверка статуса

```bash
GET /api/kill-switch/status
```

Или через Python:
```python
from kill_switch_manager import get_kill_switch_manager
ks = get_kill_switch_manager()
status = ks.get_status()
print(f"Mode: {status.current_mode.value}, Active: {status.is_active}")
```

## 📝 Рекомендации

1. **Всегда документируйте причину активации** — это критично для аудита
2. **Деактивируйте сразу после решения проблемы** — не оставляйте систему в Safe Mode
3. **Используйте LOCKDOWN только в крайних случаях** — это полностью блокирует функциональность
4. **SAFE режим — для временных проблем** — когда нужно остановить только reasoning
5. **Проверяйте статус после деактивации** — убедитесь, что система вернулась в NORMAL

---

**Помните:** Kill Switch — это инструмент безопасности, а не обычный режим работы. Система должна работать в NORMAL режиме по умолчанию!
