# Реперные точки анализа тендеров (v0.1)

Этот документ — базовая карта того, **что именно должна вытаскивать и подсвечивать система** из тендерной документации по разным сферам.

Основано на реальных примерах из папки `tender/` (8 пакетов):
- `tender1 1 stroyka` — строительство/ремонт моста
- `tender 2 nedvijkka` — недвижимость / содержание объектов
- `tender 3 injiniring` — инженерные/проектные услуги
- `tender 4 postavra` — поставка товаров
- `tender 5 mebel` — поставка мебели/оборудования
- `tender 6 it` — ИТ (товары/услуги)
- `tender 7 oxrana` — охранные услуги
- `tender 8` — универсальный шаблон (описание объекта, НМЦК, заявка, контракт)

## 1. Общие реперные точки (для любой сферы)

Эти данные должны **всегда** пытаться извлекаться, независимо от отрасли.

### 1.1. Паспорт закупки

Из документов:
- "Описание объекта закупки" / ТЗ
- "Извещение" / "Приложение к извещению"
- Проект контракта

Поля:
- `subject`: краткое наименование предмета закупки (ремонт моста, уборка, охрана, поставка мебели и т.п.)
- `fz`: режим (44-ФЗ / 223-ФЗ / иное)
- `place`: место оказания услуг / выполнения работ / поставки
- `customer`: наименование заказчика (если можем вытащить надёжно)
- `nmck`: НМЦК (пересекается с финансовым блоком)
- `iun`: ИУН (Идентификационный номер закупки) — длинный числовой код из извещения
- `iun_index`: ИУН-индекс (Индекс управленческой нагрузки) — метрика сложности контракта (см. раздел 1.5)
- `deadlines`:
  - срок подачи заявок
  - срок выполнения работ/оказания услуг/поставки
  - срок действия контракта

### 1.2. Финансовые условия

Из документов:
- Обоснование НМЦК (doc/pdf/xlsx)
- Локальные сметы / расчёты НМЦК
- Проект контракта
- Порядок обеспечения

Поля:
- `nmck` (общая ставка, числовое значение)
- структура НМЦК (по разделам, если возможно — особенно для смет)
- `advance`: аванс (процент/сумма, срок выплаты)
- `paymentTerms`: условия и сроки оплаты (по КС-2/КС-3, ежемесячно, в течение N дней)
- `bidSecurity`: обеспечение заявки (процент/сумма, форма)
- `contractSecurity`: обеспечение контракта (процент/сумма, форма)
- особые условия: удержания, залоги, штрафы за неосвоение аванса и т.п.

### 1.2.1. ИУН-индекс (Индекс управленческой нагрузки)

**ИУН-индекс** — метрика сложности управления контрактом, влияющая на решение директора.

**Компоненты расчета:**

**Риск B (Сроки оплаты):**
- 7 дней без аванса = +15
- 14 дней без аванса = +10
- 30 дней без аванса = +5
- С авансом 30%+ = -5

**Риск C (Специфические лицензии):**
- Антитеррористическая защищенность = +25
- Допуск к государственной тайне = +20
- СРО строителей = +10
- Стандартные лицензии (ЧОП, мед) = +5

**Риск D (Сроки годности/ресурс):**
- Остаток срока годности > 80% = +20
- Остаток срока годности 50-80% = +10
- Остаток срока годности < 50% = +5

**Формула:**
```
ИУН = Базовый риск (10) + Риск B + Риск C + Риск D
```

**Интерпретация:**
- ИУН < 30: Низкая управленческая нагрузка
- ИУН 30-50: Средняя управленческая нагрузка
- ИУН > 50: Высокая управленческая нагрузка (deal breaker для малого бизнеса)

**Где искать данные:**
- Сроки оплаты: Проект контракта, Порядок обеспечения
- Лицензии: Требования к участнику, Требования к заявке
- Сроки годности: Спецификация товаров, ТЗ

### 1.3. Ответственность и риски по договору

Из документов:
- Проект контракта
- Порядок обеспечения

Поля и сигналы:
- `penalties`:
  - штрафы/неустойки за просрочку (процент в день, предел от цены контракта)
  - штрафы за некачественную работу, отказ от подписания актов и др.
- `unilateralTermination`: условия одностороннего отказа заказчика
- `rnpRisks`: основания для включения в РНП
- `warranty`:
  - срок гарантии
  - перечень элементов/работ, на которые она распространяется

### 1.4. Требования к участнику и заявке

Из документов:
- "Требования к содержанию/составу заявки" + инструкция
- "Требования к участнику закупки"

Поля:
- `participantRequirements`:
  - лицензии / СРО / допуски (по отраслям)
  - требования к опыту (сколько контрактов, на какую сумму, за какой период)
  - требования к персоналу (главный инженер, специалисты, охранники и т.п.)
  - требования к технике/оборудованию
  - ограничения по нацрежиму (ОТН/СТ-1, запреты на иностранные товары)
- `bidComposition`:
  - какие документы входят в первую/вторую часть заявки
  - форма документов (оригинал/копия, скан, выписка и т.п.)

Эти данные должны попадать в JSON в блоки:
- `participantRequirements` (уже частично есть в схеме)
- доп.блок `bidRequirements` для состава заявки.

## 2. Строительство / ремонт (tender1 1 stroyka)

Документы:
- Отчёт по осмотру моста (техотчёт)
- Описание объекта закупки (мост)
- Локальный сметный расчёт (xlsx)
- Проект контракта / Договор
- Порядок обеспечения
- Требования к заявке/участнику

### 2.1. Техотчёты / осмотры / технические заключения

Ключевые реперные точки:
- тип объекта: мост, дорога, здание, сооружение
- характеристики:
  - длина, схема пролётов
  - материалы (деревянный/железобетонный, опоры, настил и т.п.)
- состояние:
  - формулировки: "удовлетворительное", "ограниченно работоспособное", "аварийное" и т.п.
  - общий износ (%), явные дефекты
- рекомендации:
  - вид работ: ремонт / капремонт / реконструкция
  - необходимость замены конструктивных элементов (пролёты, опоры, настил)
  - ссылки на СП/СНиП/ГОСТ/типовые проекты
- ограничения по эксплуатации:
  - запрет движения транспорта/пешеходов до ремонта
  - необходимость установки знаков

JSON-блок (условно `inspectionSummary`):
- `objectType`, `length`, `spanScheme`, `condition`, `wearPercent`, `recommendedWorkKind`, `normativeRefs`, `safetyMeasures`, `additionalRisks`.

### 2.2. Описание объекта закупки (строительные работы)

Реперные точки:
- вид работ: ремонт/капремонт/реконструкция
- состав работ по разделам (подготовительные, земляные, опоры, пролётные строения, тротуары, ограждения и т.п.)
- привязка к отчёту/проекту (ссылки на техотчёт, проекты, сметы)

Блок `objectSpec`:
- `workKind`, `sections`, `referenceDocs`.

### 2.3. Локальные сметы

Реперные точки:
- общая сметная стоимость ("Итого по смете", "Всего по объекту" и аналоги)
- стоимость по крупным разделам (если возможно вытащить)
- наличие материалов НДС, накладных, сметной прибыли, индексов

Блок `smetaSummary`:
- `total`, `sections[]` (опционально).

### 2.4. Контракт + порядок обеспечения (строительство)

Дополнительно к общим реперным точкам:
- привязка оплаты к КС-2/КС-3
- аванс и условия его освоения
- гарантийные обязательства по видам работ/конструкциям

## 3. Недвижимость / содержание объектов (tender 2 nedvijkka)

Документы (по списку файлов):
- Описание объекта закупки (ТЗ)
- Обоснование НМЦК (pdf)
- Проект муниципального контракта
- Требования к заявке и участнику

Отраслевые реперные точки:
- вид услуги: содержание, обслуживание, эксплуатация зданий/сооружений
- перечень объектов (адреса, площади, помещения)
- виды работ/услуг:
  - уборка, вывоз мусора, обслуживание инженерных систем, текущий ремонт
- период оказания услуг (календарный год, сезоны)

Специфические поля:
- `realEstateSpec`:
  - `objects[]` с адресами и площадями
  - `services[]` (перечень типов обслуживания)
- в контракте:
  - периодичность оказания услуг
  - KPI/показатели качества (если есть)

## 4. Инжиниринг / проектные услуги (tender 3 injiniring)

Документы:
- Извещение
- Ситуационный план (pdf)
- Приложение №1 Описание объекта закупки
- Приложение №2 Обоснование НМЦК
- Приложение №3 Требования к заявке
- Приложение №4 Порядок рассмотрения и оценки заявок
- Приложение №5 Проект контракта

Отраслевые реперные точки:
- вид услуг: проектирование, обследование, авторский надзор, инженерные изыскания и т.п.
- стадия проектирования (П, Р, РД и др.)
- исходные данные, которые предоставляет заказчик
- комплектность результата:
  - состав проектной документации
  - количество экземпляров, формат (бумага/PDF/BIM)
- сроки по этапам (например, обследование → проект → экспертиза)

Блок `engineeringSpec`:
- `serviceKind`, `stages[]`, `deliverables[]`, `inputDataFromCustomer[]`.

## 5. Поставка товаров (tender 4 postavra, tender 5 mebel, tender 6 it)

Общие документы:
- ТЗ / "Описание объекта закупки (товары, работы, услуги)"
- Расчёт/обоснование НМЦК (xlsx/docx)
- Требования к заявке
- Проект контракта

Общие отраслевые реперные точки:
- перечень позиций (наименование, количество, единица измерения)
- критические характеристики товара (марка, модель, ГОСТ, класс точности и др.)
- запреты на конкретные бренды без "или эквивалент" (красный флаг)
- требования к сроку поставки, месту поставки, упаковке

### 5.1. Мебель (tender 5 mebel)

Дополнительное:
- требования к материалам, пожарной безопасности, эргономике
- типовые наборы мебели по помещениям

### 5.2. ИТ (tender 6 it)

Дополнительное:
- разделение на оборудование/ПО/услуги
- наличие лицензий, сроков сопровождения, SLA
- требования к совместимости, поддерживаемым стандартам

Блоки:
- `goodsSpec`:
  - `items[]` с полями `name`, `qty`, `unit`, `keySpecs`
- `itSpec` (подмножество `goodsSpec` + лицензии/поддержка).

## 6. Охрана (tender 7 oxrana)

Документы:
- График поставки (фактически график услуг охраны)
- НМЦК по охране
- Проект контракта на оказание охранных услуг
- Требования к заявке (две части)
- Порядок рассмотрения и оценки заявок

Отраслевые реперные точки:
- посты охраны: количество, адреса, режим работы (круглосуточно/дневные/ночные)
- численность персонала на смену, квалификация, лицензии (ЧОП, охранники)
- перечень ТСО (камеры, сигнализация, пульты)
- требования к реагированию (время прибытия группы задержания и т.п.)
- особенности пропускного режима

Блок `securitySpec`:
- `posts[]` (адрес, режим, число охранников)
- `responseTimeRequirements`
- `equipment` (ТСО).

## 7. Универсальный шаблон (tender 8)

Файлы:
- Приложение №1 Описание объекта закупки
- Приложение №2 Обоснование НМЦК
- Приложение №3 Требования к заявке
- Приложение №4 Проект контракта

Это по сути "универсальный" 44-ФЗ-шаблон, который подтверждает, что наши общие блоки (паспорт, финансы, требования, контракт) применимы к большинству сфер.

## 8. Как использовать этот файл дальше

1. **Для backend**:
   - на его основе расширяем функции:
     - `analyze_single_file` (классификация docType, промпты для LLM);
     - `specialized_analyzers` (финансы, красные флаги, отраслевые эвристики).

2. **Для LLM-промптов**:
   - блоки из этого файла станут "чек-листом", что нужно заполнить в JSON-ответе по каждому типу документа.

3. **Для фронтенда (хаб)**:
   - каждая группа реперных точек соответствует отдельным блокам на экране:
     - Паспорт закупки
     - Финансовая оценка
     - Обеспечение
     - Сроки
     - Требования к участнику и заявке
     - Состояние объекта (для стройки)
     - Спецификация товаров/услуг (по отраслям)

В дальнейшем этот файл можно дополнять новыми отраслями и приватными шаблонами заказчика.
