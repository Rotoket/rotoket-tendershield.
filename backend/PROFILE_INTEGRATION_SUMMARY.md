## 🎉 Что сделано

### 1. ✅ Backend эндпоинты

**Новые эндпоинты:**
- `GET /api/profile` - Получение полной информации о профиле (тариф и использование)
- `GET /api/tariffs` - Получение списка доступных тарифов

**Схемы данных (`backend/schemas.py`):**
```python
class UsageResponse(BaseModel):
    analyses_count: int
    packages_count: int
    analyses_limit: int
    package_limit: int
    analyses_remaining: int  # -1 для безлимита
    packages_remaining: int  # -1 для безлимита

class ProfileResponse(BaseModel):
    user: UserResponse
    tariff: Optional[TariffResponse] = None
    usage: Optional[UsageResponse] = None
```

**Функционал:**
- Автоматическое создание записи использования для текущего месяца
- Вычисление оставшихся анализов/пакетов
- Поддержка безлимитных тарифов (limit = 0)

### 2. ✅ Frontend сервис

**Новый файл:** `frontend/src/services/profileService.ts`

**Функции:**
- `getProfile()` - получение полной информации о профиле
- `getTariffs()` - получение списка доступных тарифов

**Типы:**
```typescript
interface TariffInfo {

interface UsageInfo {
  analyses_count: number;
  packages_count: number;
  analyses_limit: number;
  package_limit: number;

  packages_remaining: number; // -1 для безлимита
}
```

### 3. ✅ Обновленный компонент Profile

**Изменения:**

## 🔧 Технические детали

### Backend логика:
1. При запросе `/api/profile`:
   - Получаем тариф пользователя (если есть)
   - Ищем или создаем запись использования за текущий месяц
   - Вычисляем оставшиеся анализы/пакеты
   - Возвращаем полную информацию

2. При отсутствии тарифа:
   - `tariff: null`
   - `usage: null` или с нулевыми лимитами

### Frontend логика:
1. При загрузке компонента Profile:
   - Вызывается `getProfile()`
   - Данные сохраняются в состоянии
   - Обновляется форма с информацией о пользователе

2. Отображение:
   - Показ загрузки во время получения данных
   - Отображение ошибки при неудаче
   - Динамическое обновление прогресс-баров
