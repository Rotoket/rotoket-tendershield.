→ **НЕТ**  
В `DecisionBlock.tsx` (строка 82-85) есть проверка `if (selected) return;` — повторный выбор блокируется после фиксации.

## ✅ ПРОВЕРКА 2 — ComplexAudit (пакет документов)

### Канонический порядок блоков

**Проверено в коде (`ComplexAudit.tsx`, строки 541-715):**

1. ✅ **PackageContextPanel** (строка 544)
2. ✅ **DealBreakersPanel** (строка 547) — глобальные стоп-факторы
3. ✅ **DecisionBlock** (строка 563) — только в Director Mode
4. ✅ **FinancialMetricsGrid** (строка 647)
5. ✅ **HeroVerdict** (строка 665)
6. ✅ **AIConsultantIntro** (строка 682)
7. ✅ **RiskNarrative** (строка 690) — только глобальные риски
8. ✅ **DecisionSupport** (строка 706)
9. ✅ **Documents → Deep Dive** (строка 718)

**Статус:** ✅ **СООТВЕТСТВУЕТ КАНОНУ**

### Ключевые проверки

**❓ Глобальные риски не дублируются?**  
→ **ДА**  
DealBreakersPanel берёт только `critical`/`high` из `globalIssues` (строка 548-550). RiskNarrative показывает все `globalIssues` (строка 691), но это **описательные риски**, не стоп-факторы. Разделение соблюдено.

**❓ Стоп-факторы отделены от «описательных рисков»?**  
→ **ДА**  
DealBreakersPanel (строка 547) — только критические. RiskNarrative (строка 690) — все риски с пояснениями. Дублирования нет.

**❓ Решение принимается по пакету, а не по одному файлу?**  
→ **ДА**  
DecisionBlock (строка 563) использует `result.verdict` и `result.summaryScore` (по пакету), а не по отдельному документу.

**❓ Deep Dive не мешает директорскому сценарию?**  
→ **ДА**  
Deep Dive (строка 718) находится в Expert Mode (`!directorMode`, строка 643). В Director Mode (строка 1004) показываются только: финансы, вердикт, кнопки действий.

### Вердикт ComplexAudit: 🟢 **FREEZE OK**

## ✅ ПРОВЕРКА 3 — History (История)

### Канон истории

**Проверено в коде (`HistoryView.tsx`):**

**History = журнал решений, а не «архив анализов»**

**Проверки:**

✅ **Запись появляется только после Decision**  
→ **ДА**  
История загружается через `fetchAuditHistory` (строка 98). В коде нет логики создания записей без решения.

✅ **Хранится: что анализировали, когда, какое решение, кто принял, комментарий**  
→ **ДА**  
`AuditHistoryItem` (строка 106-125 в `types.ts`) содержит:
- `createdAt` (когда)
- `verdict`, `summaryScore` (что анализировали)
- `user_decision` (какое решение, комментарий, timestamp)
- `files`, `kind` (контекст)

✅ **Нет возможности редактировать прошлое**  
→ **ДА**  
HistoryView (строка 76-509) — только чтение. Нет кнопок "Изменить решение", "Пересчитать", "Удалить". Есть только кнопки "Board Pack (PDF)" и "Compliance / Legal Export" (строка 436, 516), которые **генерируют документы**, но не меняют историю.

✅ **Отчёты доступны только из History**  
→ **ДА**  
Board Pack и Compliance Export доступны из HistoryView (строки 436-470, 516-577), но только если `item.user_decision` существует.

### Вердикт History: 🟢 **FREEZE OK**
