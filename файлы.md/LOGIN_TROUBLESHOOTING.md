# Диагностика проблемы входа в систему

## Проблема
Форма входа крутится в загрузке, пользователь не может войти.

## Исправления

### 1. Нормализация email в токене (backend)
- Email в JWT токене теперь всегда в lowercase
- Поиск пользователя case-insensitive (ilike)

### 2. Таймаут для getCurrentUser (frontend)
- Добавлен таймаут 8 секунд для запроса `/auth/me`
- Если запрос зависает - используется fallback объект пользователя

### 3. Fallback механизм
- Если `/auth/me` не работает или зависает, создаётся минимальный объект пользователя
- Пользователь может войти, даже если endpoint `/auth/me` недоступен

### 4. Улучшенное логирование
- Добавлены логи на каждом этапе входа
- Можно отследить, где именно происходит проблема

## Как проверить

### 1. Откройте консоль браузера (F12)
При попытке входа должны появиться логи:
```
[AuthService] Login attempt: { email: 'rotoket@mail.ru', passwordLength: 12 }
[AuthService] Token saved, getting user info...
[AuthService] Fetching user info from /auth/me...
[AuthService] /auth/me response status: 200
[AuthService] User data received: { id: 1, email: 'rotoket@mail.ru' }
```

### 2. Проверьте логи backend
Должны быть сообщения:
```
Попытка входа: email=rotoket@mail.ru
✅ Успешная аутентификация пользователя rotoket@mail.ru
✅ Токен создан для пользователя rotoket@mail.ru
```

### 3. Если форма всё ещё крутится

**Вариант A: Запрос `/auth/login` зависает**
- Проверьте, что backend запущен
- Проверьте CORS настройки
- Проверьте сетевые запросы в DevTools (Network tab)

**Вариант B: Запрос `/auth/me` зависает**
- Теперь есть fallback - пользователь должен войти через 8 секунд
- Проверьте логи backend для `/auth/me`

**Вариант C: Ошибка в обработке ответа**
- Проверьте консоль браузера на ошибки JavaScript
- Проверьте, что `onLogin` вызывается правильно
