# 🔒 Политика использования Kill Switch

## ✅ Текущий статус

**Система работает в нормальном режиме (NORMAL):**
- ✅ Все функции доступны
- ✅ LLM-анализ активен
- ✅ Управленческие выводы формируются

## ⚠️ ВАЖНАЯ ПОЛИТИКА

**Kill Switch должен использоваться ТОЛЬКО в экстренных случаях!**

### 🚨 Экстренные случаи (когда активировать):

1. **Критичные ошибки LLM:**
   - Система выдает явно неправильные решения
   - Обнаружены систематические ошибки в анализе
   - LLM возвращает некорректные или опасные данные

2. **Проблемы безопасности:**
   - Обнаружены уязвимости в reasoning layer
   - Риск утечки данных через LLM
   - Компрометация системы

3. **Критичные обновления:**
   - Критичное обновление промптов или логики
   - Миграция данных с риском ошибок
   - Временная остановка для срочной проверки

### ❌ Когда НЕ активировать:

- ❌ Обычная работа системы
- ❌ Плановое обслуживание (если можно обойтись без остановки)
- ❌ Тестирование (используйте тестовое окружение)
- ❌ Временные сбои LLM (если есть fallback)
- ❌ Профилактические цели

## 🔧 Как проверить текущий статус

```bash
GET /api/kill-switch/status
```

Ответ должен быть:
```json
{
  "mode": "NORMAL",
  "is_active": false,
  "kill_switch_enabled": true
}
```

## 📋 Процедура активации (только для администраторов)

1. **Убедитесь, что ситуация действительно экстренная**
2. **Документируйте причину активации**
3. **Активируйте через API или скрипт**
4. **Уведомите команду о причинах активации**
5. **Сразу после решения проблемы — деактивируйте**

### Команды:

**Активация (только в экстренных случаях!):**
```bash
POST /api/kill-switch/activate
{
  "trigger": "manual_admin",
  "reason": "КРИТИЧНАЯ ПРИЧИНА: [описание проблемы]",
  "target_mode": "SAFE"
}
```

**Деактивация:**
```bash
POST /api/kill-switch/deactivate
{
  "reason": "Проблема решена, возврат в нормальный режим"
}
```

Или через скрипт:
```bash
cd backend
python deactivate_kill_switch.py
```

## 📝 Важные правила

1. **По умолчанию система всегда в NORMAL режиме**
2. **Активируйте только при реальной необходимости**
3. **Деактивируйте сразу после решения проблемы**
4. **Всегда документируйте причину активации**
5. **Не оставляйте систему в Safe Mode без причины**

---

**Помните:** Kill Switch — это инструмент безопасности для экстренных ситуаций, а не обычный режим работы!
