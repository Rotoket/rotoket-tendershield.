## 🎯 О проекте

**Tender Shield Pro** — SaaS-платформа для автоматического анализа тендерной документации с использованием искусственного интеллекта. Система помогает компаниям быстро оценивать риски участия в тендерах, выявлять проблемные места в документации и принимать обоснованные решения.

### Основная идея
Автоматизировать рутинный процесс анализа тендерной документации, который обычно занимает часы работы специалистов, сократив его до нескольких минут с помощью AI.

### 🔐 1. Система авторизации и пользователей

**Где:** `backend/auth.py`, `backend/database.py`, `backend/schemas.py`

**Что сделано:**
- ✅ Регистрация пользователей через email/пароль
- ✅ JWT токены для авторизации (срок действия: 30 дней)
- ✅ Хеширование паролей (bcrypt)

- ✅ Опциональная авторизация (для обратной совместимости)

**API эндпоинты:**
- `POST /api/auth/register` - регистрация
- `POST /api/auth/login` - вход в систему
- `GET /api/auth/me` - информация о текущем пользователе

**Почему так:**
- JWT токены не требуют хранения сессий на сервере
- Bcrypt обеспечивает безопасное хранение паролей
- Опциональная авторизация позволяет использовать систему без регистрации (для демо)

### 💾 2. База данных (PostgreSQL)

**Где:** `backend/database.py`, `backend/alembic/`

**Что сделано:**
- ✅ Модель `User` - пользователи системы
- ✅ Модель `Tariff` - тарифные планы
- ✅ Модель `Analysis` - анализы отдельных документов
- ✅ Модель `PackageAnalysis` - пакетные анализы
- ✅ Модель `Usage` - учет использования (квоты)
- ✅ Автоматическое создание таблиц при старте
- ✅ Миграции через Alembic
- ✅ Создание тарифов по умолчанию

**Структура БД:**
```sql
users
  - id, email, hashed_password, name, company
  - tariff_id, is_active, created_at

tariffs
  - id, name, price, analyses_limit, package_limit
  - features (JSON), is_active

analyses
  - id, user_id, filename, industry
  - result_json (JSON), score, verdict, summary
  - created_at

package_analyses
  - id, user_id, package_id, summary_score
  - verdict, documents_json (JSON), global_issues (JSON)

usage
  - id, user_id, year, month
  - analyses_count, packages_count, tokens_used
```

**Почему так:**
- PostgreSQL - надежная реляционная БД с поддержкой JSON
- SQLAlchemy ORM упрощает работу с БД
- Alembic для версионирования схемы БД
- JSON поля для гибкого хранения результатов анализа

## 💡 Ключевые решения и обоснования

### Почему Ollama вместо OpenAI/Anthropic?
- **Локальность**: данные не покидают сервер
- **Стоимость**: нет платы за токены
- **Контроль**: полный контроль над моделью
- **Независимость**: не зависит от внешних API

### Почему FastAPI?
- **Производительность**: один из самых быстрых Python фреймворков
- **Автодокументация**: автоматическая генерация OpenAPI
- **Типизация**: поддержка Pydantic для валидации
- **Асинхронность**: нативная поддержка async/await

### Почему PostgreSQL?
- **Надежность**: проверенная временем БД
- **JSON поддержка**: гибкое хранение результатов анализа
- **Масштабируемость**: легко масштабируется
- **Сообщество**: большое сообщество и документация

### Почему React?
- **Популярность**: большое сообщество и библиотеки
- **Экосистема**: богатая экосистема инструментов
- **Производительность**: виртуальный DOM для оптимизации
- **Типизация**: TypeScript для безопасности типов

## 🐛 Известные проблемы и ограничения

### Текущие ограничения
1. **Синхронная обработка**: анализ блокирует запрос
2. **Нет кеширования**: каждый анализ выполняется заново
3. **Нет платежей**: система не готова к коммерции
4. **Ограниченная безопасность**: базовые меры защиты
5. **Нет мониторинга**: отсутствует система отслеживания ошибок

### Планируемые исправления
- Асинхронная обработка через Celery
- Кеширование результатов
- Интеграция платежной системы
- Улучшение безопасности
- Внедрение мониторинга
