# Руководство по участию в разработке

## Основные правила

### 1. Язык интерфейса
- **Весь пользовательский интерфейс только на русском языке**
- Английский может использоваться только во внутренних комментариях/переменных в коде

### 2. Юридические ограничения
- Система **не заменяет юриста** и не даёт «готовых схем» обхода закона
- Везде, где система даёт выводы / рекомендации, есть **дисклеймер**, что это аналитическая оценка
- Все юридические выводы по возможности сопровождаются ссылкой на норму закона

### 3. Персональные данные (152-ФЗ)
- При загрузке документов всегда есть текст о том, что пользователь подтверждает законность использования
- На экране авторизации реализованы чекбоксы: пользовательское соглашение и согласие на обработку ПДн

### 4. Логирование и тесты
- Для **каждой важной новой функции**:
  - должна быть **логика логирования** (через единый UI-логгер)
  - по возможности должны быть **юнит-тесты**
  - после завершения задачи должны запускаться **тесты** (`npm test`)
- Важные пользовательские действия должны логироваться в человеко‑читаемом виде

## Структура коммитов

Используйте понятные сообщения коммитов:

```
feat: добавлена новая функция анализа рисков
fix: исправлена ошибка в калькуляторе маржинальности
docs: обновлена документация по API
test: добавлены тесты для hubBuilders
refactor: рефакторинг компонента Analyzer
```

## Процесс разработки

1. Создайте ветку от `master`
2. Внесите изменения
3. Напишите тесты (если возможно)
4. Убедитесь, что все тесты проходят (`npm test`)
5. Создайте Pull Request

## Тестирование

### Frontend
```bash
cd frontend
npm test
```

### Backend
```bash
cd backend
# Добавьте тесты в папку tests/
python -m pytest tests/
```

## Стиль кода

### TypeScript/React
- Используйте TypeScript типы из `src/types.ts`
- Компоненты должны быть функциональными
- Используйте хуки React

### Python
- Следуйте PEP 8
- Используйте type hints
- Документируйте функции docstrings
